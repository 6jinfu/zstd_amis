# 功能明细 F06 · 测评（评鉴中心 · 取数）

> 归属：评鉴中心 · 测评。为盘点（F07）产出结构化测评数据；结果按指标/维度出分，供盘点分层与差距计算。
> 一句话：管理端并列三类测评项目——**考试 / 360评估 / 人才测评**，各自独立创建、结构不同但设计统一；测评对象可关联岗位带出指标，也可纯建；结果统一归 AssessmentResult。
> 依赖：人才标准（岗位关联指标）、测评工具库（F08：题库/问卷/量表库）· 下游：盘点（F07 盘点活动引用）。
> 设计红线：三类项目**并列不合类**（不用"选类型"划分）；对象来源灵活（岗位/纯建）不写死；量表答题形态（迫选/排序/李克特）**不暴露管理端**；页面清爽少文案。

---

## 1. 功能定位

- 测评 = 取数：把员工在某些指标/维度上的水平**测出来**，产出结构化分数，供盘点消费。
- **三类并列项目**（结构不同、各自入口）：
  | 项目 | 测什么 | 谁来评 | 关联库(F08) | 结果 |
  | --- | --- | --- | --- | --- |
  | **考试** | 专业能力/知识 | 系统判分 | 题库（默认试卷） | 指标/维度得分 |
  | **360评估** | 通用能力/行为 | 自评+上级+同级+下级（角色） | 问卷库 | 指标/维度得分（分源） |
  | **人才测评** | 动力/潜力 | 被测本人答 | 量表库（经典量表） | 指标/维度得分 |
- **设计统一性**（三类都遵守）：项目制（00 §12A）、统一列表布局与状态机、按钮位置（07 §7.0）；结果统一归 `AssessmentResult`。
- **对象两种建法**（用户自选，不写死）：① 关联岗位 → 带出岗位关联指标作为测评内容；② 纯建项目 → 自定义测评内容，不挂岗位。
- **不做测法反查建议**：不替用户判断该用哪种测评，用户直接选建哪类项目。

## 2. 三类项目并列的组织形态

```
评鉴中心 · 测评
├── 考试项目      （列表 + 创建）
├── 360评估项目   （列表 + 创建）
└── 人才测评项目  （列表 + 创建）
```

三个平级入口，各自项目列表。共用：项目基类字段（§3.1）、状态机（§7.6）、结果模型（§4）。差异在各自的"配置 + 执行"环节。

## 3. 数据模型

### 3.1 AssessmentProject 测评项目基类（三类共用）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| project_id | string | 系统 | 主键（前缀按类型：exam_/survey360_/talent_） |
| project_type | enum | ✅ | `exam 考试` / `survey_360` / `talent 人才测评` |
| name | string | ✅ | 项目名 |
| goal | text | — | 目标 |
| object_mode | enum | ✅ | `by_position 关联岗位` / `standalone 纯建` |
| position_ref | ref | 条件 | object_mode=by_position：关联岗位 |
| indicators | array | ✅ | 测评内容（指标项）：岗位带出 或 自选 |
| target_employees | array | ✅ | 被测员工 |
| period | object | — | 周期（start/end） |
| status | enum | ✅ | draft/running/done/archived（见 00 §12） |
| completion | object | 系统 | 完成度（已测/总） |
| created_by | ref | ✅ | 负责人 |
| created_at | datetime | 系统 | 创建时间 |

> `indicators` 是三类项目的公共"测评内容"载体：考试按它定题目范围、360按它设评估项、人才测评按它选量表覆盖维度。每个指标带其所属维度（dimension），供结果按维度聚合。

### 3.2 ExamConfig 考试项目专有

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| project_id | ref | ✅ | 所属项目 |
| paper_ref | ref | ✅ | 引用的试卷（来自题库 F08，默认试卷可直接选） |
| duration | int | — | 时长（分钟） |
| pass_score | decimal | — | 及格线（默认值可编辑） |
| indicator_map | object | 系统 | 题目↔指标映射（来自试卷，用于按指标出分） |

### 3.3 Survey360Config 360评估项目专有 ★

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| project_id | ref | ✅ | 所属项目 |
| questionnaire_ref | ref | ✅ | 引用的 360 问卷（问卷库 F08，题目关联指标） |
| roles | array | ✅ | 评估角色（自评/上级/同级/下级，可自定义） |
| rater_relations | array | ✅ | 评估关系（被测人 × 角色 × 评估人，手动维护/导入） |
| role_weights | object | — | 各角色权重（默认值可编辑，合成指标分用） |

> 360 流程：**选指标 → 创建评估角色 → 维护评估关系（给角色手动选/导入人员，不自动按组织关系拉）**。

### 3.4 TalentTestConfig 人才测评项目专有

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| project_id | ref | ✅ | 所属项目 |
| scale_refs | array | ✅ | 选用量表（量表库 F08：大五/沙因/贝尔宾/盖洛普/DISC/霍兰德/双因素/WVI/驱动力…） |
| scale_dimension_map | object | 系统 | 量表↔指标/维度映射（用于出分） |

> 量表的答题形态（迫选/排序/李克特）由 F08 绑定量表时定死，**不在此项目暴露、客户不选**。

### 3.5 AssessmentResult 测评结果（唯一归属，盘点核心输入）★

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| result_id | string | 系统 | 主键 |
| employee_id | ref | ✅ | 被测员工 |
| project_id | ref | ✅ | 所属测评项目 |
| project_type | enum | ✅ | exam/survey_360/talent |
| indicator_id | ref | ✅ | 指标（**按指标出分**） |
| dimension | enum | ✅ | 维度（**按维度出分**，指标聚合） |
| indicator_score | decimal | ✅ | 指标得分 |
| dimension_score | decimal | 系统 | 维度得分（该维度下指标聚合，供盘点按维度盘） |
| rater_source | enum | 条件 | 评价来源（360：自评/上级/同级/下级） |
| reliability_flag | enum | 系统 | 信度标记（异常/正常，AI 检验） |
| origin | enum | ✅ | `standalone 独立创建` / `from_review 盘点发起` |
| review_ref | ref | 条件 | origin=from_review 时回填盘点项目ID |

> **双粒度出分（关键跨模块点）**：结果同时给 `indicator_score`（按指标）与 `dimension_score`（按维度）。盘点（F07）配分层规则时，轴可选**指标分**或**维度分**——按指标盘或按维度盘，宫格更灵活。
> 结果**唯一归 AssessmentResult**，无论独立建还是盘点发起（origin=from_review）都存这里，盘点只持引用。

## 4. 结果出分规则（双粒度）★

```
指标分 indicator_score：
  考试   = 该指标关联题目得分汇总
  360    = 该指标下评估项各源分数 ×角色权重 合成
  人才测评= 量表映射到该指标的得分
维度分 dimension_score：
  = 该维度下所有指标分聚合（默认均值，可配）
```

> 盘点按指标盘 → 用 indicator_score；按维度盘 → 用 dimension_score。两者都由测评侧产出，盘点不再换算。

## 5. 各类项目创建流程（项目制，设计统一）

三类都走统一四步骨架，差异在③④：

```
① 创建：名称/目标/负责人/周期
② 选对象：object_mode 二选一
     · 关联岗位 → 选岗位，自动带出关联指标（可增删）
     · 纯建     → 手动选/加测评内容（指标），选被测员工
③ 配置（按类型）：
     考试   → 选试卷(默认卷/题库)、时长、及格线
     360    → 选问卷、建角色、维护评估关系（手动/导入）、角色权重
     人才测评→ 选量表
④ 运行：下发作答 / 引绩效自动拉；完成后 AI 信度检验 → 汇总写 AssessmentResult
```

## 6. 页面与交互（可直接出页面设计）

> 按钮位置遵循 07 §7.0。视觉遵循 07。文案克制。

### 6.1 页面清单

| 层级 | 页面 | 类型 | 路由 |
| --- | --- | --- | --- |
| L1 | 考试项目列表 | 列表 | `/assess/exam` |
| L1 | 360评估项目列表 | 列表 | `/assess/survey360` |
| L1 | 人才测评项目列表 | 列表 | `/assess/talent-test` |
| L2 | 创建向导（按类型） | 项目向导 | `/assess/{type}/new` |

### 6.2 L1 项目列表（三类统一布局）

- 【列表】`[col]`项目名 / 评估对象(岗位或"自定义") / 测评内容(指标数) / 完成度 / 状态`[tag]` / 负责人 / 创建时间 / 操作。
- 【操作】主操作 `[btn]创建`（筛选区下方左上）；行：`[btn]查看结果` `[btn]编辑` `[btn]删除`。
- 空态：引导 `[btn]创建`。

### 6.3 L2 创建向导（统一四步，③按类型变）

顶部 Steps：`① 创建 → ② 选对象 → ③ 配置 → ④ 运行`。底部固定 `[btn]上一步/下一步/保存草稿`。

- **①创建**：`[field]`项目名✅/目标/负责人✅/周期。
- **②选对象**：`[field]`对象方式（关联岗位 / 纯建）。
  - 关联岗位 → L3 岗位选择器 → 带出指标列表（`[btn]增删`）。
  - 纯建 → 直接选/加指标；`[field]`选被测员工（部门树+多选）。
- **③配置（按类型）**：
  - 考试：`[btn]选试卷`（L3 试卷选择器，含默认卷）+ `[field]`时长/及格线。
  - 360：`[btn]选问卷` + `[field]`评估角色（默认自评/上级/同级/下级，可增删）+ `[btn]维护评估关系`（L3：按角色手动选人 / 导入）+ `[field]`角色权重。
  - 人才测评：`[btn]选量表`（L3 量表选择器，覆盖所选指标的维度）。
- **④运行**：汇总只读 + `[btn]下发`（生成作答任务）。

### 6.4 L2 项目详情/结果页

- 顶部：项目名 + 状态 + `[btn]催办`/`[btn]结束`。
- 完成度区：已测/总；360 显示各评估关系回收情况。
- 结果区：`[col]`员工 / 各指标分 / 各维度分 / 信度`[tag]` / 操作(`[btn]查看报告`)。
- `[btn]查看报告` → L3 个人测评报告：指标分 + 维度分（360 分源展示）+ 信度提示。

### 6.5 L3 360 评估关系维护 ★

- 按评估角色分区（自评/上级/同级/下级/自定义角色）。
- 每角色下：被测人 × 评估人清单，`[btn]添加评估人`（选人）/ `[btn]导入`（模板：被测人×角色×评估人）/ `[btn]删除`。
- 不自动按组织关系拉；全手动维护/导入。

### 6.6 状态机（三类统一）

```
草稿(draft) ──下发──> 进行中(running) ──全部回收+信度检验──> 已完成(done) ──归档──> 已归档(archived)
   │                      │催办                                 │
   └── 编辑配置            └── 部分未交：不阻断，标未完成          └── 结果供盘点引用
```

### 6.7 空态与异常

| 场景 | 处理 |
| --- | --- |
| 无项目 | 列表空态 + `[btn]创建` |
| 关联岗位无指标 | 提示先在标准中心配指标 |
| 未选试卷/问卷/量表 | 禁用下发 |
| 360 评估关系为空 | 禁用下发 + 提示维护关系 |
| 部分员工未作答 | 不阻断，标未完成 + 催办 |
| 信度异常 | 结果标信度`[tag]`，不阻断，人工判断 |

## 7. 与盘点（F07）的衔接

| 路径 | 触发 | origin | 说明 |
| --- | --- | --- | --- |
| 独立跑（主） | 测评直接建项目并执行 | standalone | 结果供任意盘点活动"引用已有测评" |
| 盘点发起（补） | F07 盘点活动"新建补测"（考试/测评/360） | from_review | 测评侧执行、数据归 AssessmentResult、完成回流盘点 |

> 盘点活动引用测评时，按需取 indicator_score 或 dimension_score（对应盘点按指标/按维度盘）。

## 8. AI 能力

保留一处（给建议不给结论，00 §17）：**信度检验** `reliability_check`——汇总时对结果做信度/认知差异检验（如 360 自评与他评偏差过大），标信度 flag 供人工判断。不做自动剔除。

## 9. 验收要点

- [ ] 三类测评项目并列（考试/360/人才测评），各自入口列表，不用"选类型"合类。
- [ ] 三类遵循统一设计：项目制、统一列表布局、统一状态机、按钮位置 07 §7.0。
- [ ] 对象两种建法：关联岗位带出指标 / 纯建自选，不写死。
- [ ] 考试引用试卷（含默认卷，不逐题挑）；360 选问卷+建角色+手动维护评估关系（不自动拉）；人才测评选量表。
- [ ] 量表答题形态（迫选/排序/李克特）不暴露管理端。
- [ ] 结果双粒度出分：indicator_score（按指标）+ dimension_score（按维度）。
- [ ] 结果唯一归 AssessmentResult；盘点发起 origin=from_review 回流。
- [ ] 库（题库/问卷/量表库）不在本文展开，用选择器引用（详见 F08）。
- [ ] 信度检验为建议态，不自动剔除。
- [ ] 状态机 草稿→进行中→已完成→已归档；部分未交不阻断+催办；空态/异常齐全。
- [ ] 与 F07 衔接：结果供盘点活动引用，按指标/维度取分。
