# 功能明细 F04 · 岗位管理（标准中心 · 定对象）

> 归属：标准中心 · 定对象 · 岗位管理。合并原 F03 关键岗位（关键岗位 = 本列表的筛选视图）。
> 一句话：一份岗位数据，通过"全部/关键"双视图管理；关键岗位是 `is_key=true` 的筛选视图，操作与字段完全一致。给关键岗位配岗位标准、学习方案，是人才发展定对象的落脚点。
> 视觉红线：**清爽、一致、有呼吸感**——留白充足、一屏不堆砌、表单分区透气、双视图切换平滑。

---

## 1. 功能定位

- **关键岗位不是独立数据**，就是岗位列表用 `is_key=true` 筛出的一个视图。同一份岗位数据、同一套编辑字段、同一套操作。
- 一个"岗位管理"菜单，内部切**全部岗位 ⇄ 关键岗位**两个视图；**默认关键岗位视图**（方便直接操作定对象）。
- 两视图**操作完全一致**（列/按钮/编辑字段相同），仅筛选不同——降低认知负担。
- 岗位数据来自平台，本功能维护岗位信息 + 关键标记 + 配置入口。

## 2. 双视图（华丽切换）

```
岗位管理（一份数据）
├── 全部岗位   全量
└── 关键岗位   筛 is_key=true   ← 默认视图
```

- 切换控件：Segment/Tab，切换带**平滑过渡动画**（筛选态平滑过渡，不生硬跳变）。
- 两视图：列、操作按钮、编辑表单**完全相同**。

## 3. 岗位数据模型（复用 PRD 01 Position，增量）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| position_id | string | 系统 | 主键 |
| code | string | ✅ | 岗位编号 |
| name | string | ✅ | 岗位名称 |
| category | string | ✅ | 岗位类别 |
| duty | text | — | 岗位职责 |
| task | text | — | 岗位任务 |
| group_id | ref | — | 所在组（序列×层级，来自组织结构） |
| is_key | bool | — | 是否关键岗位（管理员标记，唯一判定） |
| key_coefficient | decimal | — | 关键系数（诊断带入，辅助，可空） |
| key_diagnosis_ref | ref | — | 关联诊断（辅助，可空） |
| standard_id | ref | — | 岗位标准（配置后关联，取消关键不清空） |
| learning_plan_id | ref | — | 学习方案（配置后关联，取消关键不清空） |

> **取消关键标记 = is_key 置 false**，standard_id/learning_plan_id 等已配数据**保留不丢**。

## 4. 页面与交互

> `[btn]`按钮 `[col]`列 `[field]`字段 `[tag]`状态。视觉遵循 07，清爽有呼吸感。

### 4.1 页面清单

| 层级 | 页面 | 类型 | 路由 |
| --- | --- | --- | --- |
| L1 | 岗位管理（双视图列表） | 列表 | `/standard/positions` |
| L2 | 岗位详情页（统一，左锚点菜单） | 详情 | `/standard/positions/{id}` |
| L3 | 选择器弹窗（能力/动力/潜力/课程等） | 弹窗 | — |

> 编辑弹窗、岗位标准、学习方案不再是独立页面，**统一收进 L2 岗位详情页**，用左侧锚点菜单切换。

### 4.2 L1 岗位管理列表

- **视图切换**：全部岗位 ⇄ 关键岗位（默认关键），平滑过渡。
- 布局遵循 07 操作按钮统一规则：
  - 【筛选区】`[field]`岗位名/编号 + `[field]`岗位类别 + `[field]`所在组 + `[btn]查询`。留白充足。
  - 【主操作】`[btn]新建岗位` 置于**筛选区下方左上**（列表上方左侧）。
  - 【列表】`[col]`岗位编号 / 岗位名称 / 岗位类别 / 所在组 / 关键岗位`[tag]` / 操作(最右列)。
- 【行操作】（最右列，两视图一致，均可点）：`[btn]编辑` → 进 L2 岗位详情页（定位到"岗位信息"锚点）。
  - 也可提供 `[btn]岗位标准` / `[btn]学习方案` 快捷入口 → 进详情页并定位到对应锚点。

### 4.3 L2 岗位详情页（统一页 · 左锚点菜单）★

> 参考"详情页+左侧锚点导航"布局：一个页面承载岗位的全部内容，左侧菜单切换分区。列表的操作按钮只是**进入本页并定位到相应锚点**。

**布局**：
```
顶部：← 返回 | 岗位名称 + 状态[tag] | 操作(右侧：保存/发布) ← 遵循07详情页操作在顶部右侧
├── 左侧锚点菜单            右侧内容区（对应锚点分区）
│   ├── 岗位信息      →    §4.3.1
│   ├── 岗位标准      →    §4.3.2（责任/任务/经历/能力/动力/潜力）
│   └── 学习方案      →    §4.3.3（课程/项目/考试）
```
- 左菜单选中态：蓝底 + 左侧蓝条（遵循 07）。可美化。
- 本次只放这 3 项；其余（岗位学员/评估/培养/认证等）属其他模块，后续再挂。

#### 4.3.1 岗位信息（锚点）
- 【表单】`[field]`岗位编号✅ / `[field]`岗位名称✅ / `[field]`岗位类别✅ / `[field]`岗位职责 / `[field]`岗位任务 / `[field]`☑标记为关键岗位。
- 取消勾选关键：提示"取消后移出关键视图，已配置的标准/方案保留"，`is_key=false`，不删数据。

#### 4.3.2 岗位标准（锚点 · 岗位建模）★
> 结构 = 任职(责-任) + 资格(4D)。**此结构在「标准库」阶段会再探讨、可能调整**，先按当前版。分区卡片，留白透气。

**【任职】**
- **职责 → 任务**：父子关联输入框。**一岗多责、一责多任**。
  - 职责(责)：文本输入，`[btn]新增职责`（可不断加）。
  - 每条职责下：任务(任)文本输入，`[btn]新增任务`（父子嵌套，可不断加）。

**【资格】**
- **经历**：平铺多输入框，`[btn]添加经历`。
- **能力**：列表清单 + `[btn]选择能力` → L3 选择器 → 选 名称+等级 → 呈现 `[col]`名称/等级/描述。
- **动力**：列表清单 + `[btn]选择动力` → 选 名称 → 呈现 `[col]`名称/描述。
- **潜力**：列表清单 + `[btn]选择潜力` → 选 名称 → 呈现 `[col]`名称/描述。

> 能力/动力/潜力选择器数据源 = **词库（F05）**：能力选词条+等级、动力/潜力选词条(无等级)。动力/潜力已内置词表。

#### 4.3.3 学习方案（锚点 · 关联培训平台）★
- `[btn]关联课程` / `[btn]关联项目` / `[btn]关联考试`（L3 选择器选培训平台内容）。
- 已关联清单 `[col]`类型(课程/项目/考试) / 名称 / 操作(移除)。
- 已关联清单 `[col]`类型(课程/项目/考试) / 名称 / 操作(移除)。

### 4.4 空态
- 全部岗位无数据：引导先在平台/组织结构维护岗位。
- 关键岗位视图无数据：引导 `[btn]去关键岗位诊断` 或编辑岗位手动标记。

## 5. 关键岗位标记入口（统一 is_key）

| 入口 | 说明 |
| --- | --- |
| 岗位详情页·岗位信息·☑标记关键 | 手动标记 |
| 关键岗位诊断结果页·气泡→抽屉→勾选（F02 §8.4） | 带诊断依据 |

两入口写同一 `is_key`；取消标记不丢已配数据。

## 6. 视觉与呼吸感（红线）

- 列表：行高舒展、操作按钮用文字按钮不挤、筛选区留白。
- 建模表单：任职/资格分区卡片，区块间距充足，一屏聚焦一件事。
- 双视图切换：平滑过渡动画，切换后布局不跳变（列/操作一致，仅数据筛选变化）。
- 一致性：全部/关键两视图视觉与操作零差异。
