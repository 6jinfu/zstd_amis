# 功能明细 F02 · 关键岗位诊断（标准中心 · 定对象）

> 归属：标准中心 · 定对象 · 关键岗位诊断。承接 F01 组织结构分析的产出。
> 一句话：在已梳理的岗位/岗位族上，用 BEARS 视角（先做经济E+能力A）诊断哪些是关键岗位，标记到具体岗位，作为人才发展"定对象"的终点。
> 设计红线：**复杂度全藏 AI 后台，前台只给一张象限图 + 一句话结论**；页面留呼吸感，一次聚焦一个视角。

---

## 1. 功能定位

- **关键岗位 = 人才发展定标准的对象**。不是所有岗位都要发展，只有关键岗位才值得投入标准/测评/培养资源。
- 关键岗位诊断是**"定对象"的终点**：F01 梳理出全部岗位/岗位族 → 本功能筛出其中的关键岗位。
- 章森原则：**关键岗位的起点是岗位，必须先梳理岗位**（依赖 F01 生效版组织结构）。
- 形态：**列表型项目**（可多次诊断、平列多个诊断项目；区别于 F01 的基准版本型）。纳入 00 §12A 项目制范式。

## 2. 与组织结构分析(F01)的衔接

| 输入（来自 F01 生效版） | 用途 |
| --- | --- |
| 岗位族矩阵（序列×层级的组） | 诊断的组织骨架 |
| 平台岗位数据（岗位/类别/人数） | 诊断对象 + AI 计算原料 |

> 若 F01 尚无生效版组织结构，本功能引导先完成组织结构分析。

## 3. 诊断颗粒度（滑块可选）★

- **滑块**在"岗位族 ↔ 具体岗位"之间选颗粒度。
- 分析可按**岗位族**聚合看（粗粒度、看分布），但**关键岗位标记必须落到具体岗位**（细粒度、精确）。
- 颗粒度分布在 F01 的宫格上：每个宫格(岗位族)含平台多个岗位，标记时下钻到岗。

## 4. BEARS 视角（可自由勾选，先做 E + A）★

用户按自己有的数据/场景**自由勾选视角**（可能缺某视角），每视角独立模型：

| 视角 | 模型 | 状态 |
| --- | --- | --- |
| **经济 E** | 供需模型（需求 × 供给） | ★先做，默认视角 |
| **能力 A** | ART 模型（行动/关系/思考）× 时间成本 | ★先做 |
| 业务 B | 价值链 × DID | 占位（横纵轴待定，不臆造） |
| 变革 R | 3Cha | 占位 |
| 战略 S | 战略解码 | 占位 |

### 4.1 经济视角(E)：需求 × 供给 象限

- **横轴 X = Needs 需求**（本公司对该岗位的需求，向右递增）
- **纵轴 Y = Supply 供给**（市场人才供给，向上递增）
- 判定内核：**需求高(右) × 供给少(下) = 关键岗位**（右下象限）。

象限（行=纵轴供给，列=横轴需求，与坐标一致）：

| 供给\需求 | 需求低(左) | 需求高(右) |
| --- | --- | --- |
| **供给多(上)** | 非关键 | 非关键（可外部招聘） |
| **供给少(下)** | 一般 | ★关键岗位（需培养） |

呈现为气泡图（红泡=关键、灰泡=去招聘），气泡大小=人数。

### 4.2 能力视角(A)：能力(ART) × 时间成本 象限

- **横轴 X = 时间成本**（培养到胜任所需时间，向右递增）
- **纵轴 Y = 能力（ART 模型）**：Action 行动 + Relationship 关系 + Think 思考，各含 3 变量、1~3 分（向上递增）
- 判定内核：**能力高(上) × 时间成本高(右) = 关键岗位**（右上象限）。

**ART 模型明细（1~3 分锚定）：**

| 组 | 变量 | 1分 低 | 2分 中 | 3分 高 |
| --- | --- | --- | --- | --- |
| Think 思考 | 创新 | 不做任何创新 | 微小创新 | 较大创新 |
| Think | 决策 | 不做很多决定 | 微小决策 | 较大决策 |
| Think | 问题 | 处理简单问题 | 较复杂问题 | 非常复杂问题 |
| Relationship 关系 | 协同 | 参与团队合作 | 跨部门协作 | 发起跨部门协作 |
| Relationship | 团队 | 不带团队 | 带小组 | 带大团队 |
| Relationship | 谈判 | 无外部谈判 | 供应商谈判 | 合作方谈判 |
| Action 行动 | 技术 | 不需技术 | 一定技术基础 | 需高技术水平 |
| Action | 环境 | 安全稳定 | 较动态 | 极危险 |
| Action | 专业 | 不需专业知识 | 一定知识储备 | 大量知识储备 |

- ART 值 = 三组变量汇总；结合人数算"紧密度"。

象限（行=纵轴能力，列=横轴时间成本，与坐标一致）：

| 能力\时间成本 | 时间成本低(左) | 时间成本高(右) |
| --- | --- | --- |
| **能力高(上)** | 非关键（快速培养/招聘） | ★关键岗位（需培养） |
| **能力低(下)** | 一般 | 一般 |

### 4.3 双视角合选(E+A)：供需比 × ART 象限

- **横轴 X = ART**（能力，向右递增）
- **纵轴 Y = 供需比**（需求 vs 市场供给的综合值：需求高且供给少→供需比高，向上递增）
- 判定：**供需比高(上) × 能力高(右) = 最关键岗位**（右上角为最需培养）。

## 5. 关键岗位系数（判定 + 排序）

- **定义**：各所选视角得分加权汇总的总分 = 关键岗位系数（量化"这个岗位有多关键"）。
- **本功能用途**：① 提供关键度依据（供管理员判断）② 关键岗位排序/优先级。
- **判定收口**：诊断只给建议，**是否关键最终由管理员标记**（见 F04 岗位管理）；诊断不自动把岗位设为关键。
- **保留字段（不在此展开）**：供盘点模块做人才 T 值加权用，标注 `for_review_weighting`，此处不实现。
- 点开关键岗位可看：系数 + 各视角得分明细 + 判定依据（为什么关键）。

## 6. AI 后台计算（前台简单）★

复杂计算全部 AI 后台完成，前台只呈现象限图 + 结论：

| AI 算什么 | 依据 |
| --- | --- |
| 需求 N | 平台岗位数据 + 编制/缺口 + 业务权重 |
| 供给 S | 市场供给（有盘点用盘点信息，无则平台数据+AI估） |
| ART 能力值 | 岗位信息按 ART 模型打分 |
| 时间成本 | 岗位能力复杂度 + 培养周期估算 |
| 供需比 | 需求与供给的综合 |
| 象限归属 + 关键系数 | 各视角得分汇总 |

全部输出为**建议态**，人工可校准。

## 7. 数据模型

### 7.1 KeyPositionDiagnosis 诊断项目

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| diagnosis_id | string | 系统 | 主键（前缀 keydiag_） |
| name | string | ✅ | 项目名 |
| goal | text | — | 诊断目标 |
| org_version_ref | ref | ✅ | 引用的 F01 生效版组织结构 |
| granularity | enum | ✅ | 颗粒度：group 岗位族 / position 具体岗位 |
| selected_views | array | ✅ | 选用视角（E/A/...，可多选） |
| view_configs | object | ✅ | 各视角模型配置（如ART勾选变量+权重） |
| view_weights | object | — | 多视角时各视角权重（默认均分） |
| key_threshold | decimal | ✅ | 关键岗位判定阈值 |
| status | enum | ✅ | draft/running/done |
| created_by | ref | ✅ | 负责人 |

### 7.2 PositionKeyResult 岗位诊断结果

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| diagnosis_id | ref | 所属诊断 |
| position_id | ref | 岗位（标记落到具体岗位） |
| view_scores | object | 各视角得分（N/S/ART/时间成本…） |
| quadrant | string | 象限归属（如"需求高·供给少"） |
| key_coefficient | decimal | 关键岗位系数（总分） |
| is_key_suggested | bool | 诊断建议是否关键（超阈值→true，仅建议，非最终） |
| for_review_weighting | decimal | 供盘点加权保留字段（此处不展开） |
| evidence | text | 判定依据 |
| confirmed | bool | 人工是否确认/调整 |

> 诊断只产出 `is_key_suggested`（建议）；岗位是否关键的最终字段 `is_key` 落在 Position（见 F04 岗位管理），由管理员标记收口。

## 8. 页面与交互

> `[btn]`按钮 `[col]`列 `[field]`字段 `[tag]`状态。视觉遵循 07，留呼吸感。

### 8.1 页面清单

| 层级 | 页面 | 类型 | 路由 |
| --- | --- | --- | --- |
| L1 | 诊断项目列表 | 列表 | `/standard/key-position` |
| L2 | 诊断向导 | 项目向导 | `/standard/key-position/new` |
| L2 | 诊断结果（象限图） | 结果 | `/standard/key-position/{id}/result` |
| L3 | 岗位详情弹窗（系数+依据） | 弹窗 | — |
| L3 | 建议校准弹窗（多视角差异） | 弹窗 | — |

### 8.2 L1 诊断项目列表

> 按钮位置遵循 07 §7.0：主操作在筛选区下方左上，行操作在最右列。

- 【列表】`[col]`项目名 / 引用组织结构版本 / 颗粒度 / 所用视角 / 关键岗位数 / 状态`[tag]` / 负责人 / 操作。
- 【操作】`[btn]新建诊断`；行：`[btn]查看结果` `[btn]编辑` `[btn]删除`。
- 空态：引导 `[btn]新建诊断`；若无组织结构生效版，引导先做组织结构分析。

### 8.3 L2 诊断向导（步骤条）

`① 创建 → ② 选颗粒度 → ③ 选视角 → ④ 视角配置 → ⑤ 生成`

- **①创建**：`[field]`项目名✅ / 目标 / 引用组织结构版本(默认当前生效)。
- **②选颗粒度**：`[field]`滑块（岗位族 ↔ 具体岗位）。
- **③选视角**：视角卡勾选（经济E默认选中、能力A；B/R/S 置灰"即将上线"）。至少选 1，视觉留白，不堆砌。
- **④视角配置**：仅显示所选视角的配置。
  - 经济E：确认需求/供给的数据来源（默认AI算）。
  - 能力A：ART 变量可勾选 + 权重；`[field]`阈值。
  - 多视角：`[field]`各视角权重。
- **⑤生成**：汇总只读 + `[btn]开始诊断`(AI后台算)。

### 8.4 L2 诊断结果页（核心：象限图 + 一句话）

**布局**：顶部视角切换 + 象限图主区 + 关键岗位清单 + 详情。留白充足。
- 顶部：`[field]`视角切换（默认经济视角）：经济E / 能力A / 综合(E+A)。
- **象限图**（按所选视角渲染对应横纵轴）：
  - 经济：横N需求 × 纵S供给，红泡(关键)/灰泡(招聘)，气泡=岗位/岗位族，大小=人数。
  - 能力：横时间成本 × 纵ART能力。
  - 综合：横ART × 纵供需比。
  - 每个泡点击 → **右侧抽屉**：该气泡对应的岗位族下岗位清单（气泡可能是岗位族，非单岗）。抽屉内【列表】`[col]`岗位/所在组/关键系数/象限/`[checkbox]标记为关键`，支持单选/全选。
- **一句话结论**：图旁用大白话说明当前视角下的判定（如"右上角 5 个岗位需求高、供给少，建议优先培养"）。
- **关键岗位清单**：`[col]`岗位 / 所在组 / 关键系数 / 象限 / 是否关键`[tag]` / 依据。
- **建议校准**：多视角结论有差异的岗位标提示 → L3 建议校准弹窗（并列各视角结论，人工定最终）。
- **AI vs 人工**视觉区分：AI 判定=常规，人工改过=主色描边+"已调整"。
- **标记收口（管理员）**：诊断只给依据(系数/象限)，**不自动进关键岗位视图**；管理员在抽屉里勾选"标记为关键" → 写 `is_key=true`（落在 Position）→ 进入岗位管理·关键岗位视图(F04)。

### 8.5 L3 岗位详情弹窗
- 关键岗位系数 + 各视角得分明细（N/S/ART/时间成本）+ 判定依据文字 + `[field]`人工调整。

### 8.6 状态机
`草稿 → 诊断中 → 已完成`（诊断产出依据）。关键标记不在诊断内收口，由管理员在抽屉/岗位管理(F04)完成。

### 8.7 空态与异常

| 场景 | 处理 |
| --- | --- |
| 无组织结构生效版 | 引导先做 F01 |
| 未选视角 | 禁用下一步 |
| AI 计算失败 | 提示 + 重试 |
| 某岗位数据不足算不出 | 标"数据不足"，不阻断，人工补/跳过 |
| 多视角结论差异 | 建议校准弹窗 |
