## 1. 模块目标与二级菜单

发展中心承接盘点差距，按"组/岗位 → 跨职级 → 个人"三个层次组织培养内容。四个二级菜单：

| 二级菜单 | 层次 | 定位 | 主要对象 |
| --- | --- | --- | --- |
| 岗位学习方案 | 组/岗位 | 某岗位标准对应的学习内容（差距→目标×形式的可复用模板） | 岗位/组 |
| 岗位地图 | 岗位（横向） | 某岗位的在岗精进成长路径 | 岗位/组 |
| 职级地图 | 序列×层级（纵向） | 跨职级的晋升发展通道 | 序列/层级 |
| 个人发展计划 | 个人 | 落到具体员工的个性化计划（IDP） | 员工 |

> 共同底层模型仍是"培养过程 = 目标 × 形式"（Get 模型）；四个菜单是该模型在不同对象层级上的应用与呈现。
> "形式"中的课程/项目即接入 LD（学习培养）模块的接口。

## 2. 共用底层模型：培养过程 = 目标 × 形式（Get 模型）

### 2.1 DevTarget 培养目标（来自差距）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| target_id | string | 系统 | 主键 |
| owner_type | enum | ✅ | 归属：group/position/level/employee |
| owner_id | ref | ✅ | 对应对象 ID |
| indicator_id | ref | ✅ | 待补的能力/任务项 |
| gap | decimal | 条件 | 个人级时来自 gap_data |
| target_level | decimal | ✅ | 目标水平 |
| priority | enum | — | 结合差距/关键岗位 |

### 2.2 DevForm 培养形式（可叠加，接 LD）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| form_id | string | 系统 | 主键 |
| target_id | ref | ✅ | 所属目标 |
| form_type | enum | ✅ | 上课/辅导/练习/项目/阅读… |
| ld_resource_ref | ref | 条件 | 接入 LD 的课程/项目资源 ID |
| sequence | int | — | 在路径中的顺序 |
| duration | string | — | 周期 |

> TD↔LD 职责分离：目标（补什么）属 TD，绑定标准维度；形式（用什么补）属 LD，提供课程/项目。`form_type` 可插拔，`ld_resource_ref` 调 LD 资源。

## 3. 菜单一 · 岗位学习方案（组/岗位层）

### 3.1 定位

按某岗位（组）的标准维度，定义其应学的内容——是"目标×形式"的**可复用模板**，不绑定具体人。后续个人发展计划从这里继承。

### 3.2 LearningPlan 数据模型

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| plan_id | string | 系统 | 主键 |
| group_id | ref | ✅ | 关联组（标准来源） |
| target_refs | array | ✅ | 该组标准维度对应的培养目标（owner_type=group） |
| form_refs | array | ✅ | 各目标的形式（课程/项目，接 LD） |
| status | enum | ✅ | draft/active/disabled |
| version | string | 系统 | 版本留痕 |

### 3.3 生成逻辑

```
读取组标准（任职责-任 + 资格4D）→ 逐维度建培养目标 → 为每目标配形式(接LD) → 形成该岗位的标准学习方案模板
```

## 4. 菜单二 · 岗位地图（在岗精进路径）

### 4.1 定位

某岗位的横向成长路径——在同一岗位/组内由"基础胜任 → 精通"的学习旅程（学习地图）。

### 4.2 PositionMap 数据模型

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| map_id | string | 系统 | 主键 |
| group_id | ref | ✅ | 关联岗位/组 |
| stages | array | ✅ | 成长阶段（如 入门/胜任/骨干/专家） |
| stage_targets | array | ✅ | 每阶段对应的培养目标+形式 |
| visual_metaphor | enum | — | 路径/航线等隐喻呈现 |

### 4.3 与岗位学习方案的关系

- 学习方案 = 内容清单（学什么）；岗位地图 = 把内容按阶段串成路径（先学什么后学什么）。
- 地图引用方案里的目标/形式，加上阶段顺序。

---

## 5. 菜单三 · 职级地图（跨职级晋升通道）

### 5.1 定位

纵向发展——基于序列×层级矩阵，描述从低职级晋升到高职级所需补齐的能力与学习内容（晋升通道）。

### 5.2 LevelMap 数据模型

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| level_map_id | string | 系统 | 主键 |
| sequence_id | ref | ✅ | 所属序列 |
| transitions | array | ✅ | 职级跃迁（from_level → to_level） |
| transition_gap | array | ✅ | 跃迁所需补齐的标准维度差（高职级标准 − 低职级标准） |
| transition_targets | array | ✅ | 每个跃迁对应的培养目标+形式 |

### 5.3 生成逻辑

```
取同序列相邻两层级的组标准 → 对比 required_level 差 → 得跃迁所需补的维度 → 配目标×形式 → 形成晋升学习通道
```

> 这是组织"晋升标准透明化"的载体，员工可见从当前职级到下一职级要补什么。

## 6. 菜单四 · 个人发展计划（IDP，个人层）

### 6.1 定位

落到具体员工——以盘点差距为输入，继承所在岗位学习方案/地图，生成个性化计划。

### 6.2 IDP 数据模型

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| idp_id | string | 系统 | 主键 |
| employee_id | ref | ✅ | 对象 |
| source_gap | array | ✅ | 来自盘点 gap_data（逐维度差距） |
| inherited_plan | ref | — | 继承的岗位学习方案/地图 |
| personal_targets | array | ✅ | 个性化培养目标（owner_type=employee） |
| ordered_forms | array | ✅ | 按顺序排列的形式（学习旅程） |
| progress | object | 系统 | 完成进度 |
| status | enum | ✅ | draft/running/done |

### 6.3 生成逻辑

```
读取员工盘点差距 → 匹配其所在组的岗位学习方案/岗位地图 → 针对有差距的维度选取目标×形式 → 排序成个人学习旅程 → 输出 IDP
```

> IDP 是员工看板"我的培养路径"的数据源。

## 6A. 培养项目（开班制 · 遵循 00 §12A 项目制范式）★

### 6A.1 定位

把一批人组织成"一期培养项目/学习班"统一开展、统一排期、统一跟踪结业。与 IDP 的关系：IDP 是"千人千面的个人持续计划"，培养项目是"把一批对象按同一方案集中培养"的批量载体。一个对象可同时存在于多个培养项目。

### 6A.2 DevProject 数据模型（继承项目基类）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| dev_project_id | string | 系统 | 主键（前缀 dev_） |
| name | string | ✅ | 项目名（如"2026后备干部班"） |
| goal | text | ✅ | 培养目标 |
| period | object | ✅ | 周期（开班/结业） |
| scope | array | ✅ | 培养对象（②，可来自人才群组/池） |
| dimensions | array | ✅ | 培养维度（③，待补的能力/任务项，来自差距或学习方案） |
| tools | array | ✅ | 培养形式（④，课程/项目/辅导/练习，接 LD） |
| source_plan | ref | — | 引用的岗位学习方案/地图作模板 |
| schedule | array | — | 排期（各形式的时间安排） |
| tracking | object | 系统 | 进度/出勤/完成度 |
| completion_rule | object | — | 结业标准（如完成率≥X / 复测达标） |
| status | enum | ✅ | draft/running/done/archived |
| created_by | ref | ✅ | 负责人 |

### 6A.3 创建流程（通用四步 + 培养扩展步）

```
① 创建项目：名称/目标/周期/负责人
② 选择对象：圈定培养对象（可从人才群组/池导入）
③ 选择维度：选待补的能力/任务维度（来自盘点差距或岗位学习方案）
④ 选择工具：为各维度选培养形式（课程/项目/辅导，接 LD）
─────────── 培养专有扩展步 ───────────
⑤ 排期：为各形式安排时间，生成学习旅程
⑥ 跟踪结业：跟进度/出勤；按 completion_rule 判定结业（可触发复测）
```

### 6A.4 与 IDP 的协同

- 培养项目可**批量生成/更新成员的 IDP**（项目维度+形式写入各成员 personal_targets/ordered_forms）。
- 结业复测结果回流测评 → 可触发下一轮盘点，形成闭环。

## 7. 菜单与项目关系图

```
组标准 ──> 岗位学习方案（学什么·模板）
                │
                ├─> 岗位地图（横向：在岗精进，按阶段串路径）
                │
序列×层级 ──> 职级地图（纵向：晋升通道，跨职级补差）
                │
盘点差距 ──┬─> 个人发展计划 IDP（继承方案/地图 + 个性化）──> 员工看板
           └─> 培养项目（开班制·批量）──批量写入──> 各成员 IDP
                                          └─结业复测──> 测评 → 下轮盘点
```
