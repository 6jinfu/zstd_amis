## 1. 产品定位

人才发展系统是一条**逻辑自洽的数据链**：定岗位 → 定标准 → 测量 → 盘点 → 培养 → 沉淀应用。核心设计铁律：**逻辑通则数据通，数据通则系统活**。模块的价值不在单功能，而在"模块与模块之间那根数据线"。

| --- | --- | --- | --- |
| Define | ① 定岗位 + 关键岗位诊断 | 岗位中心 | 组织结构矩阵、关键岗位清单 |

## 3. 全局设计原则（贯穿所有模块，开发须遵守）

| 原则 | 含义 | 对开发的约束 |
| --- | --- | --- |
| 结构决定行为 | 先在表（Excel 逻辑）跑通，再做界面 | 数据模型先行；表与表之间数据必须可流转 |
| 颗粒度做到"组" | 标准/培养的承载单位是"组"=序列×层级，**不是岗位** | 标准、测评、培养均挂"组"；岗位仅用于诊断与归组 |
| 数据贯通 | 上游产出自动流入下游，禁止孤岛 | 差距、绩效、关键岗位系数等跨模块字段必须打通 |
| 测评 = 测标准的结构 | 标准有几维就测几维 | 测法由标准维度的性质反查，不可凭空配置 |
| 人机协同，给建议不给结论 | 系统给默认值/AI 建议，用户在此基础上调整 | 关键参数（权重、阈值、归组）须有"默认值 + 可编辑" |
| 专业藏后台，大白话放前台 | 降低新用户认知负载 | 前台文案口语化，专业理论作为 tooltip/说明 |

## 4. 核心领域对象（全局数据字典 · 顶层）

> 各模块详细字段见对应 PRD，此处仅定义跨模块共享的主对象与关系。

| 对象 | 说明 | 关键关系 |
| --- | --- | --- |
| Sequence 序列 | 职类（如研发/销售/职能） | 与 Level 组成 Group |
| Level 层级 | 职级（如初级/中级/高级） | 与 Sequence 组成 Group |
| **Group 组** | 序列 × 层级，**标准/测评/培养的承载单位** | 引用 Standard；归集 Position |
| Position 岗位 | 具体岗位，用于诊断与归组 | 归属一个 Group；参与关键岗位诊断 |
| Indicator 指标 | 标准的最小可复用原子 | 被 Standard 引用 |
| Standard 标准 | 某 Group 的任职 + 资格定义 | 引用多个 Indicator |
| Employee 员工 | 被测/被盘/被培养对象 | 归属 Position/Group |
| Assessment 测评 | 某员工某指标的测量值 | 关联 Employee + Indicator |
| TalentReview 盘点项目 | 一次盘点（按项目实施） | 消费 Assessment + Performance + People |
| IDP 个人发展计划 | 目标×形式，落到员工 | 由盘点差距驱动 |

## 6. 角色与权限模型（全局）

| 角色 | 范围 | 典型操作 |
| --- | --- | --- |
| 系统管理员 | 全局 | 配置、词典、工具对接 |
| HR 管理员 | 组织级 | 建标准、发起测评/盘点、管理人才池 |

## 7. 全局字段规范（开发约定）

| 项 | 规范 |
| --- | --- |
| 主键 | 各对象统一 `{对象}_id`，string，系统生成 |
| 状态字段 | 统一枚举：`draft / active / disabled / archived` |
| 版本 | 标准、指标、盘点项目支持 `version` + 变更留痕 |
| 行为描述/任务录入 | 统一"**动词 + 宾语**"格式，AI 校验合理性 |
| 时间字段 | `created_at / updated_at`，ISO 8601 |
| 软删除 | 默认软删除（`is_deleted`），不物理删除 |
| 可配置参数 | 凡权重/阈值/系数，必须 `default_value + editable` |

> 给 AI / Agent 开发的统一约束契约。所有模块（01–06）的实现都必须遵守。出现冲突时，以本部分的工程约定为准。

## 10. 通用原则（写代码前先读）

| # | 原则 | 落地要求 |
| --- | --- | --- |
| 1 | 数据模型先行 | 先定 schema 跑通表间数据流转，再写界面 |
| 2 | 模块解耦、数据贯通 | 模块间只通过定义好的字段/接口交互，禁止隐式依赖 |
| 3 | 配置项必有默认值 | 凡权重/阈值/系数 = `default + editable`，AI 给建议 |
| 4 | 给建议不给结论 | 关键判断给默认值供用户调整，不强制 |
| 5 | 专业藏后台、大白话前台 | 前台口语化文案，专业理论放 tooltip |
| 6 | 一切可追溯 | 跨模块产出（系数/差距/绩效）必须可回溯到来源 |

## 12. 统一状态机（所有"项目/任务/标准"对象通用）

```
draft（草稿）──提交──> running（进行中）──完成──> done（已完成）
   │                       │
   └──────放弃──────> archived（归档）<──归档── done
```

| 状态 | 含义 | 可执行操作 |
| --- | --- | --- |
| draft | 编辑中，未生效 | 编辑、删除、提交 |
| running | 执行中（测评/诊断/盘点进行） | 查看、终止 |
| done | 已出结果 | 查看、归档、衍生下游 |
| archived | 归档 | 只读 |

> 配置类对象（指标/标准/工具）用简化版：`draft / active / disabled`。

## 12A. 统一项目制范式（全系统强约束）★

系统中所有"开展一次活动"的业务——**组织结构分析、关键岗位诊断、测评、盘点、培养**——统一为**项目制**：每次活动 = 一个独立项目实例，可追溯、可留存历史。所有项目共用同一套创建范式、对象基类与状态机。

> 两种呈现形态：
> - **列表型**（诊断/测评/盘点/培养）：平列多个项目实例，各自独立开展。
> - **基准版本型**（组织结构分析）：入口即当前生效版可视化，唯一"当前生效版本"+ 历史版本存档；重新分析生成新版本草稿，确认生效后替换旧版。不用列表当门面。

### 12A.1 通用创建范式（向导步骤条）

```
通用四步（所有项目必有）：
  ① 创建项目（名称/目标/周期/负责人）
  ② 选择对象（圈定范围：岗位 / 员工 / 组）
  ③ 选择维度（要诊断/测/盘/培养的维度，来自标准结构）
  ④ 选择工具（每维度匹配的方法/工具）

盘点专有扩展步（仅盘点项目）：
  ⑤ 矩阵组合（选维度两两交叉，组宫格/拟合）
  ⑥ 校准（结果出来后的解释/校准，留痕）
```

> 设计要求：前端用统一的「项目向导」组件（Steps 步骤条），四步为公共步，⑤⑥为盘点注册的扩展步。其他项目类型也可注册自己的扩展步，但①–④的语义与字段必须一致。

### 12A.2 各项目类型的范式映射

| 项目类型 | ②对象 | ③维度 | ④工具 | 扩展步 |
| --- | --- | --- | --- | --- |
| 组织结构分析 | 组织范围(部门/岗位) | 分析法维度 | 5种分析法(可多选) | ⑤宫格设置 ⑥建议校准；基准版本型 |
| 关键岗位诊断 | 岗位清单 | BEARS 视角 | 各视角方法（DID/供需/ART…） | — |
| 测评项目 | 被测员工 | 标准维度（能力/动力/潜力…） | 测法工具（考试/360/大五…） | — |
| 盘点项目 | 盘点员工 | APP 字段维度 | 测评数据源（引用/新建） | ⑤矩阵组合 ⑥校准 |
| 培养项目 | 培养员工 | 差距维度 | 培养形式（课程/项目，接LD） | （可选）排期/结业 |

### 12A.3 项目对象基类（所有 XxxProject 继承）

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| project_id | string | 系统 | 主键（各类型用各自前缀：diagnosis_/assessment_/review_/dev_） |
| name | string | ✅ | 项目名 |
| goal | text | ✅ | 项目目标 |
| period | object | — | 周期（start/end） |
| scope | array | ✅ | 对象范围（②） |
| dimensions | array | ✅ | 维度（③） |
| tools | array | ✅ | 工具/数据源（④） |
| extensions | object | — | 扩展步配置（如盘点的矩阵组合/校准） |
| status | enum | ✅ | draft/running/done/archived（见 §12） |
| created_by | ref | ✅ | 负责人 |
| created_at | datetime | 系统 | 创建时间 |

> 各模块的具体项目对象（KeyPositionDiagnosis / AssessmentProject / TalentReview / DevProject）在基类上扩展专有字段，不得改动基类字段的命名与语义。

### 12A.4 统一列表与详情

- **项目列表页**：统一列 = 项目名 / 类型 / 对象范围 / 创建时间 / 状态(Tag) / 负责人 / 操作。
- **状态驱动操作**：draft→编辑/删除/提交；running→查看/终止；done→查看/衍生下游/归档。
- **运行前置校验**：进入 running 前各类型可定义就绪条件（如盘点的数据就绪度 `readiness_status=ready`）。

## 13. 统一字段类型与校验

| 字段语义 | 类型 | 校验规则 |
| --- | --- | --- |
| 权重 weight | decimal(0–1) | 同组权重和建议=1，超出给警告不阻断 |
| 系数 coef | decimal | ≥0 |
| 分值 score | decimal | 落在所属 scale 量表范围 |
| 量表 scale | enum | `5级行为锚定 / 通过-不通过 / 分值` |
| 行为/任务描述 | string | **动词+宾语**，AI 校验合理性 |
| 阈值 threshold | decimal/array | 高/中/低分档，给默认值 |

## 14. 统一交互模式（保证界面风格一致）

### 14.1 列表页标准布局

```
[页面标题 / 面包屑]
[筛选区：按名称 + 按类型/状态]   [主操作按钮：新增]   [次操作：词典/导入]
[数据表格：列… | 操作列(编辑/删除)]
[分页]
```

> 参照指标库现状：筛选(名称+类型) + 新增 + 词典管理 + 表格(操作列编辑/删除)。所有列表页统一此结构。

### 14.2 配置类页面标准模式

- 左侧结构树/步骤条，右侧表单。
- 凡可配参数：显示「系统默认值」+「可编辑」+「AI 建议」三态。
- 引用型字段（如标准引用指标）用"选择器弹窗"，不在当前页新建原子。

### 14.3 项目类页面（诊断/测评/盘点）标准流程
