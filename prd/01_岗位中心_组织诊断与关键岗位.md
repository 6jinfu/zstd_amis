# 人才发展系统 · PRD 01 · 岗位中心（组织诊断 + 关键岗位）

> 模块① · Define 阶段 · 数据链起点
> 依赖：无（地基模块） · 下游：人才标准、测评、盘点全部依赖本模块产出

---

## 1. 模块目标

1. 维护组织结构：序列 × 层级矩阵，沉淀"组(Group)"。
2. 梳理岗位并归组（关键岗位诊断的前提）。
3. 通过多视角循证识别关键岗位，输出关键岗位系数与优先级。
4. 维护指标库（标准的原子）与模型库（组的标准，详见 PRD 02）。

> 设计前提（章森）：**关键岗位的起点是岗位，必须先梳理岗位**；标准承载单位是"组"非岗位。

## 4. 组织结构页（序列 × 层级矩阵）

### 4.1 视图

- 矩阵：行=序列，列=层级，单元格=组(Group)，格内显示：组名、归属岗位数、在岗人数。
- 点击单元格 → 进入该组详情（岗位列表 + 关联标准）。

### 4.2 人效视图（增值，可切换）★

同一矩阵叠加经营数据，秒变人效系统：

| 单元格可叠加字段 | 来源 |
| --- | --- |
| 人数 headcount | 岗位统计 |
| 人力成本 labor_cost | 外部导入/HR 录入 |
| 人均成本 cost_per_capita | 计算 = 人力成本 / 人数 |
| 利润贡献 profit | 外部导入 |

> 该视图对接组织发展(OD)，为可选开关。

## 5. 关键岗位诊断（BEARS 多视角循证）

### 5.1 诊断项目对象 KeyPositionDiagnosis

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| diagnosis_id | string | 系统 | 主键 |
| name | string | ✅ | 诊断项目名 |
| goal | text | ✅ | 诊断目标（GPS-Goal，决定选哪些视角） |
| selected_views | array | ✅ | 选用的视角（B/E/A/R/S 可多选） |
| position_scope | array | ✅ | 纳入诊断的岗位清单 |
| status | enum | ✅ | draft/running/done |
| created_by | ref | ✅ | 发起人 |

### 5.2 BEARS 五视角（每个视角=一个打分维度）

| 视角 | 关键假设：什么是关键岗位 | 方法/模型 | 输出 |
| --- | --- | --- | --- |
| **B** 业务 | 处于关键业务环节的岗位 | 价值链×业务权重，DID模型 | business_score |
| **E** 经济 | 组织需要但市场供给少 | 供需模型（需求度×供给度） | economics_score |
| **A** 能力 | 能力复杂、培养周期长 | ART复杂度模型 | ability_score |
| **R** 变革 | 高度参与变革成败 | 3Cha框架 | reform_score |
| **S** 战略 | 高频参与战略实现 | 战略解码，A/B/C类计分 | strategy_score |

> 客户不打分时：AI 提供建议分（人机协同）。

### 5.3 各视角打分子表（以岗位为对象）

每个被选视角，对每个岗位产出一个 0–N 的分值，存 PositionViewScore：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| diagnosis_id | ref | 所属诊断 |
| position_id | ref | 被评岗位 |
| view | enum | B/E/A/R/S |
| score | decimal | 该视角下的关键系数 |
| evidence | text | 循证依据（关联到的关键行动/业务环节） |

### 5.4 经济视角(E)专项：气泡图数据 ★

气泡图是 E 视角的可视化与 TD↔OD 衔接点：

| 维度 | 字段 | 说明 |
| --- | --- | --- |
| X 轴 | demand_score 需求度 | 组织对该岗位的需求 |
| Y 轴 | supply_score 供给量 | 市场人才供给 |
| 气泡大小 | headcount 人数 | |
| 气泡颜色 | bubble_type | 红泡=需求高·供给少（优先培养）；灰泡=需求低·供给多（去招聘） |

### 5.5 综合关键系数（整合多视角）

| 字段 | 说明 |
| --- | --- |
| 各视角权重 | 可配置，default 等权 |
| key_position_coef | 综合系数 = Σ(视角分 × 视角权重) |
| key_position_flag | 阈值判定是否关键（阈值可配） |
| dev_priority | 发展优先级排序（结合人数） |

诊断完成 → 回写 Position 表的 `key_position_flag` 与 `key_position_coef`。

### 5.6 诊断流程（遵循 00 §12A 项目制范式 + GPS 模型约束）

```
① 创建项目：明确 Goal（目标决定选几个视角）
② 选择对象：确认岗位清单（Start Point：岗位必须先梳理）
③ 选择维度：勾选 BEARS 视角（B/E/A/R/S 可多选）
④ 选择工具：各视角对岗位循证打分（HR 引导业务部门参与；AI 给建议分）
─────────────────────────────────────────────
⑤ 运行：配置视角权重 → 系统算综合关键系数 → 阈值判定 + 优先级排序
⑥ 回写 Position；输出关键岗位清单 + 气泡图
```

> 对应范式：①创建 ②对象=岗位 ③维度=BEARS视角 ④工具=各视角方法。诊断无"矩阵组合/校准"扩展步。
> Process 约束：HR 的职责是**引导业务部门参与论证**，系统不直接给结论，给建议。

## 6. 指标库（标准的原子）

### 6.1 列表页字段（对齐现有界面）

| 列 | 说明 |
| --- | --- |
| 指标名称 | 如"问题分析""沟通""回款""电路设计" |
| 分类 | 能力 / 任务 / 资格 |
| 类型 | 见 §6.3 联动 |
| 行为项 | N 条行为（能力类有；任务/资格类为"—"） |
| 操作 | 编辑 / 删除 |

筛选：指标名称 + 类型（全部/能力/任务/…）。操作：新增指标、词典管理。

### 6.2 Indicator 主表

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| indicator_id | string | 系统 | 主键 |
| name | string | ✅ | 指标名 |
| category | enum | ✅ | 能力 / 任务 / 资格 |
| type | enum | ✅ | 随分类联动（§6.3） |
| measure_method | enum | ✅ | 考试/360/情景模拟/心理测评/领导测/HR核验/引绩效 |
| scale | enum | ✅ | 5级行为锚定 / 通过-不通过 / 分值 |
| description | text | ✅ | 定义（前台大白话） |
| dict_ref | ref | — | 词典引用，统一术语 |
| ext_tool_ref | ref | 条件 | 动力/潜力类绑定外部量表 |
| status | enum | ✅ | draft/active/disabled |
| version | string | 系统 | 版本留痕 |

### 6.3 分类 × 类型 × 测法联动表（硬约束）

| category | type | measure_method | 是否带行为项 |
| --- | --- | --- | --- |
| 能力 | 通用能力 | 360 | 是（行为锚定） |
| 能力 | 专业能力 | 考试 / 情景模拟 | 是 |
| 任务 | 结果 | 领导测 / 引绩效 | 否 |
| 资格 | 经历 | HR/领导核验 | 否 |
| 资格 | 动力 | 心理测评（沙因） | 否（接外部量表） |
| 资格 | 潜力 | 心理测评（大五） | 否（接外部量表） |

### 6.4 BehaviorItem 行为项子表（仅能力类）

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| level | enum | 量表等级（L1~L5） |
| behavior_desc | string | **动词+宾语**，AI 校验 |
| anchor | text | 该等级典型行为样例（打分参照） |

任务类不挂行为项，改挂绩效对接字段：`result_indicator`(绩/结果) + `process_indicator`(效/过程)。

### 6.5 指标库规则

- 指标与岗位**解耦**，只做原子；绑定发生在模型库（组标准）层。
- 指标被模型引用时，可查"被哪些组引用"。
- **MBTI 等类型化测评不纳入**，只收可提升变量。
- 词典管理统一术语，防止同义异名导致无法横向聚合。
