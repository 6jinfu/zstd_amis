# 人才发展系统 · PRD 02 · 人才标准（任职 + 资格）

> 模块② · Define 阶段
> 依赖：岗位中心（组、指标库） · 下游：测评中心（测什么由标准决定）

---

## 1. 模块目标

为每个"组(Group)"建立人才标准。标准顶层 = **任职(2) + 资格(4D)**，即 2+4 框架：

- **任职 = 事**：责-任结构，描述"要做什么事"。
- **资格 = 人**：4D，描述"什么样的人能做"。
- 因果链：人有资格 → 发生行为 → 把任职这件事搞定。

> 承载单位是"组"，不是岗位。一个组一套标准。

---

## 2. 标准总结构

```
Standard 标准（挂在 Group 上）
├── 任职（事）= 责-任结构
│     ├── 责 Responsibility（结果）→ 对接绩效"绩"(结果指标)
│     └── 任 Task（任务）→ 对接绩效"效"(过程指标)，动词+宾语
│        （一岗多责、一责多任）
│
└── 资格（人）= 4D
      ├── 经历 Have done
      ├── 能力 Can do  → 通用能力 / 专业能力
      ├── 动力 Will do → 沙因模型
      └── 潜力 Fit to  → 大五人格
```

> 关键约束：**能力属于资格(Can do)，不属于任职**。任职只到"责-任"两层。

## 3. 数据模型

### 3.1 Standard 标准主表

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| standard_id | string | 系统 | 主键 |
| group_id | ref | ✅ | 所属组（唯一） |
| name | string | 系统 | 组名+标准 |
| completeness | enum | 系统 | 完整度：基础/完整（见 §5） |
| status | enum | ✅ | draft/active/disabled |
| version | string | 系统 | 版本留痕 |

### 3.2 任职 - 责 Responsibility

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| resp_id | string | 系统 | 主键 |
| standard_id | ref | ✅ | 所属标准 |
| name | string | ✅ | 责任名（如"回款""维护客户关系"） |
| perf_result_indicator | ref | — | 对接绩效结果指标"绩" |
| sort_order | int | — | 排序 |

### 3.3 任职 - 任 Task

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| task_id | string | 系统 | 主键 |
| resp_id | ref | ✅ | 所属责任（一责多任） |
| name | string | ✅ | **动词+宾语**（如"参加招标""催回款""中秋拜访"），AI 校验 |
| indicator_ref | ref | — | 关联任务指标 |
| perf_process_indicator | ref | — | 对接绩效过程指标"效" |

### 3.4 资格 - 4D 项 QualificationItem

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| qual_id | string | 系统 | 主键 |
| standard_id | ref | ✅ | 所属标准 |
| dimension | enum | ✅ | 经历/能力/动力/潜力 |
| sub_type | enum | 条件 | 能力时必填：通用能力/专业能力 |
| indicator_ref | ref | ✅ | 关联指标库的指标 |
| required_level | enum | ✅ | 该组要求达到的标准值（量表等级/分值） |
| weight | decimal | — | 该项在资格中的权重（盘点 T 值用） |

> 标准值 `required_level` 是后续"差距 = 标准值 − 测评值"的被减数。

## 4. 维度 ↔ 测法映射（供测评中心读取）

| 维度 | 归属 | 子类 | 测法（measure_method） |
| --- | --- | --- | --- |
| 责-任·任务 | 任职 | 结果/过程 | 领导测 / 引绩效 |
| 经历 | 资格 | — | HR/领导核验 |
| 能力 | 资格 | 专业能力 | 考试 / 情景模拟 |
| 能力 | 资格 | 通用能力 | 360 |
| 动力 | 资格 | — | 心理测评（沙因） |
| 潜力 | 资格 | — | 心理测评（大五） |

> 外部建模法向上兼容：KSAO 的 K/S→专业能力、A→通用能力、O→动力+潜力；冰山模型显性→能力、隐性→动力+潜力。系统只认"任职(责-任)+资格(4D)"母结构，外部模型先判"事/人 → 通用/专业"再映射。

---

## 5. 完整度规则（结构要全，允许只填一部分）

| 完整度 | 必填项 | 适用 |
| --- | --- | --- |
| 基础 | 任务 + 通用能力 + 动力 + 潜力 | 大部分客户，做起来最快 |
| 完整 | 基础 + 经历 + 专业能力 + 责任全集 | 关键岗位深做 |

> 规则：结构字段全部预留并可见；非必填项允许留空。系统按已填项判定完整度，不阻断保存。

## 6. 模型库页面（组标准的承载界面）

```
模型库
├── 组列表（序列×层级，显示完整度、引用指标数、关联人数）
└── 组标准编辑
    ├── 任职页：责 → 任（树形，动词+宾语录入，AI 校验）
    │           责绑定绩效"绩"，任绑定绩效"效"
    └── 资格页：经历 / 能力(通用·专业) / 动力 / 潜力
                每项引用指标库指标 + 设 required_level + weight
```

交互：
- 从指标库**引用**指标，不在此新建指标（指标是原子，复用）。
- AI 校验任务描述是否符合"动词+宾语"。
- 给默认 required_level / weight 建议，用户可调（给建议不给结论）。

## 7. 验收要点

- [ ] 标准挂在组上，一组一标准。
- [ ] 任职为责-任两层，能力归在资格不在任职。
- [ ] 责绑结果指标、任绑过程指标，能与绩效系统打通。
- [ ] 4D 各项引用指标库并设标准值，供测评/盘点读取。
- [ ] 支持基础/完整两档，非必填可留空不阻断。
