## 1. 结论

该交付包可作为学员端的功能素材库、旧系统还原基线和视觉参考，但不能原样并入当前人才发展系统。

当前管理端已经具备“组织与岗位分析—人才标准—评鉴—岗位学习方案”的配置链路，学员端应补齐“接收方案—理解差距—执行任务—提交成果—完成验证—结果回流”的执行链路。学员端的核心不是再建设一个通用学习门户，而是让员工知道自己为什么学、要达到什么要求、按什么路径发展以及如何证明已经达到要求。

建议将交付包中的功能分为三类：

1. **纳入人才发展核心链路**：人才画像、岗位发展通道、岗位要求、前后测、学习方案、个人发展计划、任务与进度。
2. **保留但按当前口径重构**：职级地图、技能树、资源推荐、我的项目、团队发展。
3. **不纳入人才发展首期**：通用课程门户、学习积分运营、知识贡献、发起学习活动、空白的业务价值链发展通道等与既有培训平台重叠或尚无数据来源的能力。

## 2. 交付包现有功能盘点

### 2.1 我的发展

| 页面 | 现有内容 | 可用性判断 | 当前处理建议 |
| --- | --- | --- | --- |
| 人才画像 | 学时、学分、积分、学习偏好、岗位通道、人才特征、能力图表、资源推荐 | 内容较完整，但更像学习门户画像 | 保留框架，改为标准、实际能力、优势、差距和发展进度 |
| 推荐 | 直播、偏好课程、热门内容 | 与人才发展关联弱 | 不作为人才发展一级页面；由培训平台承接 |
| 岗位地图 | 12 个岗位节点、当前岗位、岗位详情 | 交互可用，视觉表达有参考价值 | 保留并接入管理端岗位地图、标准和学习方案 |
| 职级地图 | 8 个职级/能力节点及详情 | 可运行，但当前管理端只维护职级，尚无独立职级发展方案 | 作为后续能力，待职级标准和职级方案口径确定后接入 |
| 业务价值链发展通道 | “敬请期待”空态 | 无有效功能 | 首期不展示，不保留占位入口 |
| 个人发展计划 | 页面为空 | 无有效功能 | 重建为学员端核心页面，不沿用空页面 |
| 我的项目 | 时光易培、学习地图、安排课程、考试、直播 | 可浏览，主要属于培训执行平台 | 只汇总与当前发展计划有关的任务，并跳转既有平台执行 |
| 我的技能树 | 图谱节点、胜任力指数、岗位意义、关键职责 | 有展示价值，但口径为旧技能图谱 | 改为能力图谱，数据统一来自指标库、人才标准和评鉴结果 |

### 2.2 岗位/职级节点详情

岗位节点已提供“岗位要求、前测、学习方案、后测”四个页签；职级节点提供“职级信息及要求、学习方案”两个页签。

可保留的交互骨架是：

```text
发展通道 → 选择岗位 → 查看岗位要求 → 查看发展方案 → 执行前测/学习/实践/后测
```

但现有数据使用“基础要求、技能、素养、知识”旧口径，与当前管理端人才标准的“职责任务、经历经验、能力、动力、潜力”不一致，必须统一从当前人才标准读取，不能保留两套标准模型。

### 2.3 学习方案

现有页面包含课程、任务和个人发展计划三个区块，课程筛选与课程卡片可运行；任务只有测试文案，个人发展计划无数据。

当前主要缺口：

- 不显示采用的人才标准及版本；
- 不解释课程或任务对应哪项标准要求；
- 不区分岗位基线方案与个人差距方案；
- 没有发展目标、模块、顺序、里程碑和完成规则；
- 前测、后测均为空，无法验证能力变化；
- 缺少岗位实践、导师辅导、成果提交和审核；
- 没有管理端发布、分配和学员接收关系。

### 2.4 团队发展

目前只有团队人数、学时、学分和学习进度四个空指标，不具备人员、计划、差距或辅导能力。团队发展属于管理者角色，不应与普通学员入口混在一起。首期建议不开放；后续如建设，应依据角色权限展示团队发展计划、风险人员、待辅导事项和成果审核。

## 3. 与现管理端的主要冲突

| 冲突 | 学员端交付包 | 当前管理端 | 统一原则 |
| --- | --- | --- | --- |
| 标准结构 | 基础要求、技能、素养、知识 | 职责任务、经历经验、能力、动力、潜力 | 学员端只读当前已发布的人才标准 |
| 岗位数据 | 产品经理、营销通道等旧演示数据 | 当前岗位库及组织分析结果 | 以当前岗位数据和岗位地图为唯一来源 |
| 学习方案 | 课程卡、测试任务、空 IDP | 岗位关联课程、项目、前测、后测 | 增加标准版本、发展目标、模块、任务和分配关系 |
| 能力差距 | 多个雷达图，但来源不清 | 标准要求 + 最新有效评鉴结果 | 差距必须可追溯到标准和结果来源 |
| 前后测 | 空列表 | 管理端可关联已有考试 | 学员端展示被分配的测评并回收结果 |
| 项目与课程 | 大量通用学习门户内容 | 复用培训平台资源 | 人才发展只编排和追踪，具体学习跳转既有平台 |
| 个人计划 | 页面和区块均为空 | 当前延期 | 调整为学员端核心对象，管理端独立 IDP 列表可后置 |
| 团队发展 | 空仪表盘 | 无对应管理关系 | 首期隐藏，后续按管理者权限独立建设 |

## 4. 确认后的学员端信息架构

首期建议只保留四个主入口：

```text
我的发展
├─ 发展首页
├─ 我的画像
├─ 发展通道
└─ 我的发展计划
```

### 4.1 发展首页

- 当前岗位、采用标准和目标岗位；
- 当前发展计划及整体进度；
- 本周待办、即将到期、待参加测评；
- 待提交实践成果和待查看反馈；
- 最近学习及继续学习入口。

### 4.2 我的画像

- 当前适用的人才标准；
- 标准要求与实际能力对比；
- 优势项、待发展项和暂无有效结果项；
- 结果来源、有效时间和完成的认证/发展经历；
- 不默认展示宫格落位、人才分类、潜力标签等管理端敏感结论。

### 4.3 发展通道

- 当前岗位、相邻岗位和目标岗位；
- 岗位要求、个人准备度和待补齐要求；
- 进入对应岗位发展方案；
- 职级通道在职级标准与方案口径具备后再开放。

### 4.4 我的发展计划

- 计划来源、采用标准、目标岗位、开始/截止时间；
- 发展目标及其当前值、目标值；
- 前测、课程、项目、岗位实践、导师辅导、后测；
- 必修/选修、顺序、里程碑、完成条件；
- 进度、状态、成果提交、反馈和重新评估；
- 通用课程播放、考试作答和项目执行跳转既有培训平台。

## 5. 管理端与学员端闭环

```text
发布人才标准
  → 基于标准构建岗位发展方案
  → 发布并按岗位/条件/人员分配
  → 学员接收个人发展计划
  → 完成前测、学习、实践和后测
  → 导师/上级确认成果
  → 结果回流人才画像和管理端效果分析
```

为支持该闭环，至少需要区分以下对象：

| 对象 | 用途 |
| --- | --- |
| DevelopmentSolution | 基于标准版本形成的岗位/群体发展方案 |
| SolutionModule | 发展目标、培养模块及其覆盖的标准要求 |
| PlanAssignment | 将方案发布给岗位、规则人群或具体人员 |
| IndividualDevelopmentPlan | 学员接收后的个人计划及差异化任务 |
| LearningTask | 课程、项目、前测、后测、实践、辅导等执行项 |
| DevelopmentEvidence | 实践成果、审核意见、测评结果和完成证据 |

## 6. 首期与后续范围

### 首期必须打通

- 发展首页；
- 我的画像；
- 岗位发展通道；
- 我的发展计划；
- 课程/项目/测评跳转；
- 实践成果提交与审核结果；
- 学习任务状态和计划进度；
- 管理端方案发布、分配和进度查看。

### 后续增强

- 职级地图；
- 团队发展；
- 导师在线辅导与计划共创；
- AI 陪练与智能学习助手；
- 业务价值链发展通道；
- 学习效果和资源有效性分析。

### 不在人才发展系统重复建设

- 通用课程中心、直播中心、资料中心；
- 学习积分商城和运营活动；
- 通用知识贡献和学习社区；
- 课程播放、考试作答、直播观看等培训平台已有能力。

## 7. 仍需业务确认

1. 个人发展计划由 HR 直接分配、员工与上级共创，还是两种方式都支持；首期建议先支持管理员分配、学员确认接收。
2. 学员是否可以自主选择目标岗位；首期建议只查看通道，由管理员或上级确认目标岗位。
3. 岗位实践成果由直属上级、导师还是 HR 审核；建议方案发布时指定审核角色。
4. 学员可见的人才画像边界；默认不展示宫格落位、人才分类、潜力结论和他人对比。
5. 团队发展面向直属经理还是部门负责人；未确认前首期隐藏入口。
6. 培训平台可提供的课程进度、项目进度、考试结果和跳转协议。

## 8. 原型质量确认

- 交付文件和本地资源完整，SHA-256 校验通过；
- `student.html` 可独立运行，人才画像、岗位地图、岗位节点、学习方案筛选、我的项目和技能树等主要切换可用；
- 个人发展计划主页面为空白，岗位学习方案中的个人发展计划也为空；
- 前测、后测和团队发展只有空态或空指标；
- 多个通用学习动作仅显示本地演示提示，不构成真实业务闭环；
- 页面以鼠标点击为主，部分按钮缺少明确的可访问名称、焦点设计和 44px 点击范围，不能直接作为上线质量基线；
- 结论为“可作为参考基线，需按当前产品模型重构”，不是直接合并或上线批准。
