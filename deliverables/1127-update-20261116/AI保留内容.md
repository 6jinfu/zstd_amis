## 人才标准 AI 帮建

本节以当前人才标准原型为交互基线，供 1127 期需求梳理。页面是本地规则演示；真实模型、附件解析、业务服务和持久化尚未接通。以下截图为既有原型核验图，展示对应交互状态，示例内容不作为业务结果。

### 一、流程

人才标准列表点击“AI帮建” → 选择岗位（选填）并输入建模要求 → 确认生成设置 → 设置生成偏好 → 有能力候选时进行排序和重要性评分 → 查看并调整草稿、确认应用范围 → 带入新建页或选择更新方式 → 在编辑页保存。

首页：岗位可选；未选岗位仍可按通用场景生成，默认暂不关联。三条示例只描述建模要求，不描述岗位，点击示例直接发送；也可自行填写并发送。附件和语音图标保留，当前附件未解析。 生成设置：选择新建或更新已有标准，查看目标岗位和业务场景，在已启用维度中选择本次生成内容，至少选择一项；可补充建模信息后确认继续。需求理解卡当前隐藏，不应把内部整理结果说成已向用户展示。 生成偏好：内容详略为简洁、精要、适中、充实、详细五档，默认简洁；选中能力要求时可选择只写行为、带上情境、包含成果三档，默认只写行为。补充要求选填，可返回调整生成内容。 能力排序与评分：仅本次生成含非空能力候选时出现。先按重要性排序，再逐项评 1–5 分；分数降序，同分沿用原排序。评分表示优先级，与能力要求等级无关。未选择能力或候选为空则跳过。 草稿：对话与右侧全文预览并存；可按维度打开编辑器或输入明确的定向修改，修改后更新预览。新建时确认应用范围；更新时保留原范围，须明确选择直接覆盖或保留更新。带入编辑页不等于保存，需在编辑页保存后生效。

### 三、工作流及接入

目标链路： 前端提交岗位（可空）、用户要求和可选资料 → 业务服务读取租户内有效岗位、维度与指标候选 → 工作流整理需求并返回结构化结果 → 用户确认生成设置与偏好 → 生成能力候选并由用户排序评分 → 根据确认结果生成草稿 → 校验结构、指标及来源 → 用户审阅、修改并确认范围或更新策略 → 业务服务再次校验版本，带入编辑页，由用户保存。

#### 能力雷达图与分等级描述

能力分组： 按指标库中能力的实际类别组织，每类使用独立雷达图展示该类别的能力项及岗位要求等级；同一能力不重复归组。类别内少于3项时按列表展示，不虚构能力凑图；类别缺失时列入“待分类”，不猜测类别。各组均不足3项但总能力不少于3项时保留总体雷达图。雷达图表达岗位要求等级，不是个人能力得分。

生成详略： 简洁、精要目标为1–2张雷达图；适中、充实目标为2–3张；详细目标为3张及以上。应结合岗位实际和可用指标决定能力数量，不为满足图数加入无关能力。当前原型只截取已有示例候选，五档能力上限分别为6、10、14、18、20，不能保证达到目标图数；每套标准暂保持最多20项能力。

分等级能力描述： 每项能力按其实际已配置的全部等级生成对应描述，不能强制统一为L1–L5，也不把岗位要求等级当作唯一需要描述的等级。“只写行为”描述各等级行为；“带上情境”增加相应场景；“包含成果”进一步说明可观察的预期结果。等级间应体现职责复杂度、独立程度或影响范围的差异，避免同句换词。

工作流设计： 读取当前租户的能力类别、指标身份、已配置等级及现有定义 → 按岗位和详略生成有依据的类别与能力候选 → 逐能力逐已配置等级生成指定结构的描述 → 校验能力及等级归属、描述完整性和重复 → 输出分组、能力、岗位要求等级与各等级描述 → 用户审阅调整 → 保存当前人才标准。AI生成的分等级描述仅属于当前人才标准，不更新共享指标库；既有词典定义和AI建议必须区分，缺少等级配置或依据时提示，不虚构官方定义。

当前边界： 本地原型已按已有类别分组展示，等级描述控件只展示多等级表达示例；演示指标数据没有各等级描述，尚未接入真实生成、编辑、保存或指标库写回。既有Dify工作流仍是旧契约，须补齐上述输入、输出和校验，尚未实测。

已确认： 生成的分等级描述仅保存在当前人才标准，不更新共享指标库；每套标准暂保持最多20项能力。更新已有标准时分等级描述如何合并仍待设计。

#### 同类岗位：相似岗位查找与确认

业务目标： 选择“同类岗位”时，寻找与当前目标岗位实际工作相近的岗位；岗位类别只能作为辅助信息，不能将同类别全部岗位直接关联。

触发： 新建标准且已选择目标岗位时，用户选择“同类岗位”。未指定目标岗位时不推断同类岗位；更新已有标准沿用原应用范围。 准备候选： 业务服务读取当前租户、当前用户有权使用的真实岗位及可用资料，并提供目标岗位与候选岗位的稳定 ID、名称、类别及实际可取得的职责、工作内容等；不得跨租户检索或让模型创造岗位。 相似判断： 工作流结合目标岗位和当前人才标准，对可用岗位资料进行相似性分析，优先参考实际职责、任务和工作内容；类别、名称可作辅助，不作为唯一依据。返回真实候选岗位 ID、名称、可核对的相似依据及必要的差异或资料不足提示；不得把模型分数当成已校准的概率。 人工确认： 应用范围卡展示候选及理由，允许用户检查并调整；用户明确确认实际关联的岗位。候选如何默认勾选、目标岗位是否固定包含待产品确认，不由工作流擅自决定。 带入与保存： 业务服务校验确认的岗位 ID、租户、权限与数据版本，只将确认的岗位带入标准编辑页；用户在编辑页保存后生效。关联前岗位失效或权限变化时提示重新选择，不静默替换。

异常分支： 岗位资料不足以判断时说明缺失内容，不凭名称或类别伪造相似结论；没有合适候选时说明无结果，并允许用户选择其他范围或稍后设置。具体补充资料和人工选择方式待确认。

现状和接入： 现有原型按岗位类别直接全选；原版 Dify Workflow 没有相似岗位检索或判断环节。上述是本期需补齐的目标流程，涉及业务数据提供、候选生成、前端展示及确认、服务端校验；不代表现有 DSL 或页面已实现。

验收： 同一类别但职责明显不同的岗位不会仅因类别相同自动关联；不同类别但工作相近的岗位可作为候选；只返回真实且有权使用的岗位；确认前不写入范围，确认后仅带入实际选定 ID；资料不足、无结果和岗位失效均有明确反馈。

待确认： 相似性依据的可用字段和判定口径、资料不足时的操作方式、候选默认勾选及是否固定包含目标岗位。

职责边界： 页面和业务服务管理对话状态、选项、排序评分、版本、权限、范围和最终保存；模型负责需求理解、内容建议及定向修改。资料依据与推断应区分，字段缺失或冲突需澄清，不擅自编造企业定义。生成失败或版本不一致时保留已有内容，不采用半份结果。

现有工作流状态： 下方是 2026-10-26 交付的普通 Workflow 参考文件，支持分析需求、生成草稿及定向修改；其旧版双档详略和内容侧重契约未对齐当前五档详略、三档能力描述方式及排序评分，不能直接作为本期完整实现。工作流未在目标 Dify 实例导入或模型实测；真实调用将消耗模型额度，须另行确认。

接入需补齐：五档与三档偏好的接口及生成语义；候选生成、排序评分与最终草稿的状态衔接；结构化描述字段的存储；附件解析与来源；草稿及源标准版本校验；失败与重试、费用控制，以及目标环境导入和端到端验证。

### 四、验收与待确认

验收重点：选岗与不选岗均能继续；示例不包含岗位描述；至少选择一个生成维度；偏好可保留并传递；无能力时跳过排序评分；评分影响能力顺序而不改变要求等级；分项修改保留其他内容；新建或更新须明确范围及策略；进入编辑页后仍需保存。

待确认：① 非结构化需求如何整理并引导补充，当前理解卡已隐藏，尚无替代交互；② 能力描述方式的正式字段、展示与保存方式；③ 1127 期工作流接入范围和目标环境，以及模型额度授权。当前工作流文件不是已经完成上述接入的证据。
