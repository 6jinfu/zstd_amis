# 人才池来源与项目内名单统一

日期：2026-10-28，PRD V1.82。

人才中心为跨项目汇总，盘点项目为人才池来源。两处共用池ID、名单和组建流程；列表以来源项目替代目标岗位，移除复评。培养方案暂缓，池内新建IDP、学习方案和培养跟进入口收起，原数据保留在历史。

## 实现与边界

- 共用talent-pools.js建池/组建/来源跳转，复用现有UI抽屉、按钮、表格及浏览器talent-center-v1；没有新增依赖。项目原来只修改页面人数的处理已移除。
- 年度项目4名、销售项目10名代表人员与现有盘点结果逐字段核对，未把35/42名统计总数伪造为完整名单；四个原项目人才池纳入同一数据集合，实际人数按当前成员计算。
- 旧技术骨干后备池、单独等原用户记录保留，未记录来源时显示未关联，不猜来源；原目标、标准、复评、成员、计划和跟进数据没有清空。
- 人才库仍保留5名原共享人员，项目中其余代表人员不链接到未知档案。档案所属池展示同步来源项目；独立个人计划流程保留。
- 未接真实后端、项目全量人员/校准结果或跨浏览器同步。人才看板旧目标岗位与复评统计本轮未改，不能作为新项目来源人才池的业务依据。

## 已验证

- 新建表单使用名称、来源项目、负责人、期望人数、备注；必填校验生效，取消不创建。项目入口自动带入并锁定来源。
- 从区域负责人后备池组建王磊：名单仅包含销售铁军盘点人员，分类筛选与切回全部保留选择；保存后实际人数从2变3。刷新及来源项目入口均显示同一3人名单，再打开时王磊为已在池且不可重复勾选。该业务演示变更保留，未创建测试命名记录。
- 项目内名称查询/重置正常，人才池名称和来源链接均可用；详情默认在池成员，不再出现新建IDP/复评/学习方案操作。
