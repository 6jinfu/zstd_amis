# 人才中心修订计划与客户需求对应

日期：2026-09-30。输入：FlowUs 2026-09-28 日报原文、桌面 9 月 28 日原始沟通纪要、起始 PRD V1.32（本轮同步至 V1.33）、用户本轮授权全面优化；静态桌面原型，保留现有身份与标准存储。

## 问题与本轮交付

1. 缺少以岗找人的连续操作：人才库增加目标岗位及标准上下文，逐人展示满足、差距、缺证，并带入对比及人工入池；缺证不能替代差距，也不能生成胜任结论。
2. 跟进仅有自由文本：明确差距进入定向 IDP，缺证另行记录补证需求。IDP 记录目标、导师、负责人、30/60/90 天阶段和成果，关联人员、采用标准和可选人才池。阶段完成不改变评鉴成绩或达标状态。
3. 看板只有人数及覆盖：改为管理工作台，人才概览包含组织分布、盘点分类、待补评鉴与事项；岗位储备包含关键岗位、池成员和证据准备情况。使用公共蓝色和中性色，无单边色条卡片或装饰箭头。
4. 档案内容分散且来源固定：采用最近已结束盘点记录展示分类与来源；标准差距、IDP、入池依据、跟进保持同一人员与标准上下文；不编造学习行为数据。
5. 对比、入池丢上下文：共同标准显式携带，入池显示池目标冲突，要求用户确认是否按池目标重新核对；不静默换标准。

## 日报八项缺口映射

| 日报缺口 | 本轮实现落点 | 依赖 / 后续 |
| --- | --- | --- |
| 选用留全链路 | 找人 → 比较 → 入池 → IDP → 跟进；人员与证据可导出 | HR 正式任用审批及生效接口需要客户确认；不自动改变岗位 |
| 自动匹配岗位 | 管理员指定目标岗位后的人员要求比较 | 跨岗位自动推荐需要明确必备条件、证据策略和范围 |
| 胜任结论 | 满足 / 待发展 / 缺证分开，逐项可解释 | 企业资格认定与人工责任另立，不生成胜任百分比 |
| 员工自主申请 | 管理端目标与培养记录数据可供学员端后续承接 | 企业申请周期、资格与审批，学员端另行实现 |
| 动态路径 | 保留目标岗位及已有岗位学习方案关联 | 发展中心维护路径关系，不能由人才池替代 |
| 标签检索 | 业务标签与能力条件仍可筛选，结合共同目标标准 | 标签来源明确为演示记录；量化证据与人工标签分开 |
| 档案无盘点评估 | 同一人员汇集盘点、评鉴、差距、池与IDP | 学习行为及外部任职数据未接通，不伪造 |
| 人才报表缺失 | 组织、分类、评鉴、关键岗位后备与待处理事项联动 | 无历史可比数据不画趋势；无已发布个人计划不算培养完成率 |

## 验收流程

HR 选择架构师及标准 → 查看研发人员差距 → 同标准对比 → 入池确认 → 从差距建立 IDP → 保存后档案与池内可见 → 完成说明留存 → 看板待处理数量更新。另验证缺证、无标准、日期错误、重复入池、持久化和旧数据兼容。

视觉检查人才库、档案、对比、池详情、看板；只验桌面，实际截图记录。项目 PRD 与交接同轮更新。未调用付费 API，不新增字体和框架依赖。

原始记录新增诉求与时间定位见 `../../2026-09-30_景旺原始沟通补充与需求闭环.md`。岗位后备覆盖不同于编制储备比；手工 90 天 IDP 不等于打通客户既有培训项目，已在当前 PRD 明确。
