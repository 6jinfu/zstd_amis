# 人才发展操作手册维护约定

仅适用于本套手册。用户后续明确要求优先于本文。

## 从最小信息开始

1. 先运行 `python3 deliverables/talent-development-manual-20261105/维护索引.py` 查看当前发布位置和待确认事项。
2. 按变更图号查询，例如 `python3 deliverables/talent-development-manual-20261105/维护索引.py --figure 1.5-2`；用 `--changed` 找本地与上次飞书同步基线不同的图片。
3. 只读受影响章节、对应截图和必要的页面记录。历史日志、整篇PRD、全套截图及完整飞书正文不作为每轮默认输入；批量检查图片时先用联系图定位，再放大问题图。

## 正文与截图

- 正文用“入口、操作步骤、必要业务规则、配图”。删除访问日期、采集背景、当前环境示例、泛泛提醒等额外说明。人工核验事项单独列入清单；用户确认后再发布正文修订。
- 线上系统是功能与截图依据。本地原型和历史手册不能代替未核验的线上流程。
- 截图保持1730×872，只含网页内容，无浏览器地址栏或标签栏。复用业务文件名和既有图号；新增长抽屉下部图使用“（续）”，避免全篇重编号。
- DOM可见不代表抽屉已展开完成。先等数据加载，再另取截图观察标题、关闭按钮、右边界及底部操作；看到完整画面后再保存。长抽屉上下补图，保留文字可读性。
- 先保留原始截图，再用程序叠加标注。只强调易错等级、必要确认、保存或关键规则；通常每图1处，无必要不标。单个重点可只用红框，需要指向时加箭头，需要操作顺序时才编号。原图、SVG标注层分别保留。
- 本套手册已获用户明确同意使用程序叠加标注；真实UI不通过AI重绘。AI额度、实际上传、发布或结束业务项目等沿用已有授权边界，不为截图额外执行。

## 增量同步

1. 先列受影响的章节、图片及待核验点。未变化的内容直接复用，文字变化不自动触发重拍。
2. 更新本地Markdown、图片与图注；只重拍变化界面，只重画受影响标注。用SHA-256识别资源变化。
3. 飞书更新前按章节或关键词回读当前块，确认缓存ID仍有效；精确替换图片块或正文块，补图插在原图注后。保留原文档、未变化资源和评论，不默认整篇重建。
4. 直接调用 `lark-cli docs +fetch` / `lark-cli docs +update`，保持命令名和选项直接书写，仅对参数值做必要转义。不要把整条命令包成带引号的Shell命令、额外的`zsh -lc`或重定向，避免已有审批前缀失效。复用已有授权；只有真正新增的权限需求才再请求。
5. 按变更范围回读验证。跨章节批次可在末尾做一次完整检查，原始响应落盘，向对话只输出差异与结果；不要逐步输出大段DOM、正文或JSON。
6. iA Writer复用原资料库和相对图片路径，刷新预览并查看变化位置。ZIP在本轮结束时重建一次，核对引用、名称、比例和图片数量。
7. 验证通过后更新`维护状态.json`、`核对记录/配图元数据.json`中的远端块映射与同步哈希。缓存用于定位，写远端前仍须回查；失败不提前推进同步基线。
