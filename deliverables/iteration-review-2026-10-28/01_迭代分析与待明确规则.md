## 一、总体判断

这份说明已覆盖主要页面和正常流程，可作为迭代范围草稿；还不足以单独成为完整提测依据。主要缺口是：多对多关系的下游影响、跨页面一致的数据口径、异常和历史兼容，以及哪些截图元素本期不做。

本次需要分别理解三类变化：

| 变化 | 涉及内容 | 验收重点 |
| --- | --- | --- |
| 业务对象变化 | 岗位与标准一对一改多对多 | 关系、旧数据、方案归属和历史依据不能串用 |
| 新流程和数据展示 | 两种 AI 帮建、人才档案、人才池汇总 | 来源正确、状态正确、保存与跳转边界明确 |
| 界面调整及范围收缩 | 分析弹窗、职级树；移除业务标签、发展记录和差距操作 | 按本期文字验收，不能把截图里的旧元素全部做回来 |

特别明确的本期边界：应用范围仅“指定岗位、暂不关联”；业务标签暂不加；人才档案发展记录页签暂不加；标准差距明细的操作栏暂不做；标准草稿的“修改建模信息”按钮去掉。建标准到建评估的一体化引导属于后续考虑，不自动加入本期。

## 二、优先补齐的规则

以下优先级是评审建议，P0 指不明确会影响数据正确性或核心验收，不是对已有缺陷的定级。

| 编号 | 建议优先级 | 发现的问题及依据 | 需要补充的结论 | 不明确的影响 |
| --- | --- | --- | --- | --- |
| Q01 | P0 | 多对多已明确，但本期说明没有展开学习方案和学员端适配；本地当日已有确认：方案归属“岗位＋标准” | 本期是否包含管理端方案、Web/H5 岗位节点的标准及方案切换；若拆期，如何保证旧流程可用 | 标准能建好，课程却可能取错方案或互相覆盖 |
| Q02 | P0 | 旧数据兼容只说明归入岗位序列标准 | 旧标准身份、岗位关联、方案、学习记录、进行中评估、历史报告的保留映射；旧标准新名称如何生成；重复迁移和回退规则 | 列表迁移成功不代表业务数据兼容；可能重复建档或改写历史 |
| Q03 | P0 | 本期 360 帮建明确读取能力、动力、潜力；当前 PRD 与本地工作流只按能力出题 | 三类均纳入本期时，需同步指标选择、题型/题数、问卷存储、结果归属和报告；动力/潜力不应直接套用能力等级 | 页面显示三类，工作流只生成能力题；结果无法正确消费 |
| Q04 | P0 | 明确“选项分数最高 10 分”，现有截图还有 1–5 分打分题，人才雷达使用等级 | 10 分适用于哪些题型；默认分数、允许修改范围、多选汇总、打分题量程、问答是否计分；原评分如何换算等级 | 同一问卷可能混用分制，影响能力、差距和盘点 |
| Q05 | P0 | 档案默认采用“岗位最新关联的标准” | “最新”按关联时间还是标准更新时间；相同时间、解除默认关联、无候选、多岗位人员和手动选择后的默认策略 | 不同页面默认不同，编辑旧标准还可能意外改变默认项 |
| Q06 | P0 | 能力雷达以标准为轴，缺少证据显示待补充证据，但实际结果选择口径未写 | 同指标多份结果取最高还是最新；有效期和完成状态；稳定指标身份如何关联；缺值如何绘图；成绩到等级的映射 | 指标改名丢证据、失效成绩仍被采用、缺证被当成低能力 |
| Q07 | P0 | “人才池集合显示所有记录”；现 PRD 的项目内池与独立池不自动同步 | 汇总是否含项目内池；同一记录按原身份引用还是复制；来源列、查看/编辑权限、修改同步、删除和成员去重规则 | 可能出现重复池、人数不一致或历史结果被修改 |
| Q08 | P1 | 说明仅列两种应用范围，本地 PRD 和列表截图仍有按条件匹配 | 新建/编辑入口按本期只保留两种；若线上已有条件范围，旧记录如何读取、编辑及转存 | 为去掉入口误删旧规则，或测试人员仍按旧 PRD 测第三种 |
| Q09 | P1 | 可创建“暂不关联”标准；360 无数据报错截图提示完善应用范围和能力 | 无岗位但有能力的标准能否建问卷；无范围、无指标、当前无人匹配分别如何提示；只有动力/潜力时如何处理 | 合法通用标准被挡住，或错误范围流入评估 |
| Q10 | P1 | 档案统计包含标准要求和状态，说明没有计数公式 | 职责任务按职责还是任务计数；经历、能力、动力、潜力的证据来源；总数=已满足+待发展+待补充证据；无可比数据是否显示百分比 | 图表、明细和统计不一致；缺证被计为不达标 |
| Q11 | P1 | 宫格最多 15 格，说明称各格文案见图；可见示例主要展示九宫格 | 6/9/12/15 格各自的名称和说明；能力与绩效档数、轴交换、筛选联动、校准前后使用何种落位 | 不能仅凭一张九宫格截图验收全部动态规格 |
| Q12 | P1 | 人才池按能力、绩效、宫格落位筛人，维度和分层联动 | 能力分层引用本项目规则还是固定等级；切维度是否清空旧分层；原始/校准落位；跨筛选勾选、重复人员和实际人数口径 | 用失效条件筛选；同一个人被重复计入 |
| Q13 | P1 | “详见工作流”没有锁定本次发布的工作流版本；本地说明和本期文字已有差异 | 锁定两份 DSL/工作流版本、输入输出、目标环境与编辑器映射；定义失败、超时、部分生成、重复点击、重试和离开后恢复 | 原型可演示但真实生成失败；重试产生重复记录 |
| Q14 | P1 | 两个草稿按钮均进入编辑页，“修改建模信息”按钮删除 | 带入不等于保存；如何放弃；删除按钮后参数选错如何恢复；AI 修改与手工编辑的保留规则；生成中标准变化如何处理 | 取消后仍覆盖旧标准，或用户只能重做却未说明 |
| Q15 | P1 | 标准与人才数据涉及多个部门和共享对象，说明无角色规则 | 标准维护/关联/删除、人才查看、池汇总及评估的角色和组织范围；直接链接和接口也须限制 | “所有人才池”被误解为跨权限可见所有数据 |
| Q16 | P1 | 职级重构成二级树，当前文字主要描述展示问题 | 序列与职级新增/编辑字段、重名/编码、等级序、已有岗位引用、删除保护、旧数据映射；按真实客户规模验收 | 树看起来清楚，但岗位引用断开或大量数据仍不可用 |
| Q17 | P2 | 人才概览明确无数据显示“--”，截图仍有业务标签和最近跟进等旧元素 | 本期字段白名单；哪些来自人员主数据、360、盘点或人才池；最近跟进等内容是否一并移除 | 测试依据截图把已排除内容恢复 |
| Q18 | P2 | “评鉴与盘点”文字说暂时只有360记录，截图另有盘点记录表 | 是仅限制评鉴类型为360、仍保留盘点记录，还是本期整个分区只展示360记录；有效期从哪里取 | 测试人员对盘点表是否应出现得出相反预期 |
| Q19 | P2 | 标准名称50字、说明1000字、关联岗位999；人才池期望人数1–9999 | 必填、空白、重名、中文/英文/表情的计数规则；整数校验；超限前后端一致；旧超长记录如何保留 | 边界测试无法写成确定预期 |

## 三、建议补入提测范围的关联回归

以下是为了覆盖本次变化而提出的回归建议，不代表新增业务功能，也不表示已经验证通过。

| 编号 | 回归场景 | 建议验证结果 |
| --- | --- | --- |
| R01 | 旧一岗一标数据升级 | 原标准、关联、学习方案、学习进度可追溯；归入岗位序列标准；不凭同名自动合并 |
| R02 | 同一岗位关联A/B两套标准 | 要求分别读取；如果方案本期上线，A/B方案分别保存、刷新后互不覆盖 |
| R03 | 同一标准关联岗位甲/乙 | 标准内容共享；如果方案本期上线，两个岗位的方案仍独立 |
| R04 | 修改共享标准、解除一条关联、复制或删除标准 | 影响对象明确；不顺带删除另一岗位关系或既有业务；复制/引用保护规则先确认 |
| R05 | 学员在标准间切换 | 若本期包含学员端，Web/H5要求和方案同步；不清空进度、不自动报名项目、不创建IDP |
| R06 | 编辑当前标准要求L3→L4 | 当前差距按所选标准变化；旧问卷、评估、计划和历史报告仍保留原依据 |
| R07 | 标准轴ABCDE，人员结果含ABCF且D/E缺证 | 只显示ABCDE标准轴；F不加入雷达；D/E显示缺证而非自动判不达标 |
| R08 | 生成5项指标的默认问卷 | 若每项按3/1/1/1，合计30题；取消2项后18题；前提是三类指标及计题规则已确认 |
| R09 | AI超时、单批失败、重复点击、切换来源标准 | 不把残缺题本当完整成功；不重复保存；原草稿保留与重试行为符合约定 |
| R10 | 宫格6/9/12/15格、交换轴、校准后再筛人才池 | 人数与完整盘点数据一致，分层不残留，按已确认的原始/校准口径取数 |
| R11 | 同人跨池、汇总池、无权限池 | 在池人数按各池规则计算，跨池统计按所需口径去重，无权限记录不泄露 |
| R12 | 大量序列、职级、标准和关联岗位 | 用脱敏客户规模验收搜索、展开、分页与响应；不凭少量演示数据宣称性能达标 |
| R13 | 弹窗关闭后重开、任务完成和失败 | UI优化不改变后台任务生命周期；历史分析仍可查，不能把关弹窗当取消 |
| R14 | 本期关闭或不新增的入口 | 业务标签、发展记录、差距操作、修改建模信息按钮按本期边界验收；不删除原历史记录 |

## 四、提测前建议形成的最小共识

先确定本期是否包含学习方案/学员适配、360是否覆盖动力与潜力、人才池汇总是否包含项目池。随后补齐评分到等级、默认标准、证据来源和历史兼容规则。

提测材料还需填写实际版本/发布包、测试环境、功能完成状态和遗留问题。本文没有这些实施证据，因此不能把“本期计划清单”写成“已上线功能”。不需要为此先补一套完整IDP、导师或认证系统。
