# 发展方案编排：独立概念页

此页面只用于讨论方案。它位于 `deliverables/development-solution-concept/`，不改动现有“学习方案”页面、当前 PRD 或项目数据。销售经理及 7 项标准要求是示例。

## 问题判断

沿用 TypeSafe 的“把模糊问题拆成可判断问题”的方法分析前两稿；这里没有调用 TypeSafe API。

| 之前的页面 | 现在的处理 | 原因 |
| --- | --- | --- |
| 首屏主要是说明、标准选择和大输入框 | 首屏直接显示培养路径和待确认要求 | 编排模块是这页的核心工作。 |
| 多个同等重量的白色卡片从上到下堆叠 | 一个简短的方案上下文，下面是路径与标准对照的双栏工作区 | 减少滚动与重复标题，让两者的关系可同时看到。 |
| 模块序号使用圆形徽标，信息靠小标签堆叠 | 使用清晰的顺序编号、阶段名称、任务行和留白 | 对齐项目已有的克制风格，减少装饰。 |
| 完整标准表默认展开，已处理项占据大量空间 | 待确认项直接呈现，已处理项可展开查看 | 用户能先解决遗漏，同时保留全量核对入口。 |
| 页面混用临时符号图标 | 左侧导航沿用原项目的 SVG 图标 | 与项目的导航视觉保持一致。 |

## 产品结构

方案仍以人才标准为依据，但配置对象是**培养模块**，不是一串课程。每个模块记录目标、关联要求、培养任务及达成条件。同一要求可由诊断、训练、实践和验证等多个模块承接；课程、项目、前后测成为模块中的任务。

页面只演示编排和检查。标准版本变更后的修订规则、动力和潜力要求如何处理、证据如何认定，需要在进入正式产品前确认。发布与分配不在此页实现。示例草稿只保存在浏览器本地存储中。
